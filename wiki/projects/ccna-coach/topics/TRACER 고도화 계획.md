# 🚀 TRACER 고도화 계획 (로그인·DB·상시 운영·관리자·문제 저장소)

상위: [[ccna-coach]]

> 2026-11-20 사용자와 정한 계획. 같은 날 코드 완료, 배포(계정 준비)는 사용자 몫 — `agents/ccna-coach/SETUP.md`. **조건: Claude 구독 외 추가 비용 0** (모든 서비스 무료 등급, 결제 수단 등록 안 함).

## 목표
- 구글 계정 로그인, 사용자별 데이터 저장(DB)
- 내 Mac 없이 **항상 동작**(터널·`start-public.sh` 은퇴)
- 관리자 페이지: 사용자 관리, 접속·활동 기록, 권한 부여·회수
- **문제 저장소**: 이전에 만든 문제를 재사용해 제미나이 호출 절약

## 구조
```
[브라우저] ─구글 로그인─▶ [Supabase Auth]
    │  (로그인 토큰)
    ▼
[Vercel: 화면 + /api 파이썬 함수] ─▶ [제미나이 무료 키]   ← 키는 Vercel 환경변수에만
    │
    ▼
[Supabase DB: 사용자·권한·활동 기록·풀이 기록·XP·문제 저장소]
```

## 서비스 선택
| 후보 | 판단 |
|---|---|
| **Vercel(Hobby) + Supabase(Free)** ✅ | 카드 불필요, 구글 로그인 내장, 파이썬 함수로 `server.py`·`gemini_client.py` 재사용 |
| Firebase | 서버 함수가 유료 요금제(Blaze) 필요 → 제외 |
| Cloudflare Pages+Workers+D1 | 무료·일시정지 없음, 대신 로그인·관리자 직접 구현(작업 2배) |
| GitHub Pages + Supabase Edge Functions | Vercel 불필요, 대신 서버를 TypeScript로 새로 작성 |

무료 운영 주의점 (착수 시 공식 요금 페이지로 재확인):
- Supabase 무료 프로젝트는 **7일 무활동 시 일시정지** → GitHub Actions(공개 저장소 무료)로 하루 1번 깨우기.
- Vercel Hobby는 **비상업용만**. 개인 공부 도구라 해당 없음.
- 두 곳 모두 **결제 수단 미등록** → 한도 초과 시 청구 없이 멈춤.
- 볼트 자동 푸시 → Vercel은 `ccna-coach` 관련 폴더가 바뀔 때만 빌드(Ignored Build Step).
- 제미나이 무료 한도가 먼저 참 → 사용자별 하루 한도 유지.

## 단계
0. **계정 준비(사용자 직접, 안내 받음)**: Vercel(GitHub 계정), Supabase 프로젝트, Google Cloud OAuth 클라이언트 → Supabase 구글 로그인 연결. 키 값은 대시보드에만, 저장소엔 `.env.example`에 변수 이름만.
1. **DB 설계**
   - `profiles`: 이메일·이름·역할(owner/admin/user)·상태(active/pending/blocked)·가입일·마지막 접속
   - `permissions`: AI 문제·내 문제 해설 사용 여부, 하루 AI 한도
   - `activity_log`: 누가·언제·무엇(로그인·문제 받기·채점·해설), 문제 내용은 요약만
   - `attempts`(풀이 기록), `progress`(XP·레벨·배지)
   - 문제 저장소: `questions`·`question_seen`·`question_reports` (아래 절)
   - RLS: 본인 데이터만, 관리자는 전체. 정답·해설 열은 서버만 읽음.
2. **서버 이전** (`server.py` → Vercel `/api`): 토큰 확인 → 권한·차단·한도 확인 → 저장소/제미나이 → 활동 기록. 정답은 서버에만, 서브넷 계산은 화면이 직접. `refuse_paid_billing` 유지.
3. **화면**: "Google로 로그인", XP·진도 계정 저장(기기 간 이어짐), 첫 로그인 때 브라우저 XP 1회 이전, 문제 신고 버튼.
4. **관리자 페이지** (`/admin`, owner·admin만)
   - 사용자: 목록·검색, 가입일, 마지막 접속, 오늘 사용량
   - 권한: 기능별 켜기/끄기, 하루 한도, 차단/해제, 관리자 지정
   - 활동 기록: 사용자별 타임라인, 기간·행동 필터
   - 대시보드: 일별 접속자, AI 사용량, 무료 한도 대비 남은 양
   - **문제은행**: 문제 보기·고치기·숨기기, 신고 검토, 정답률 이상 문제 표시
5. **배포·유지**: Vercel(`*.vercel.app`), Supabase 깨우기 Actions, 기존 github.io `/ccna/` → 새 주소로 안내
6. **정리·검증**: 실제 구글 로그인, 권한 회수 시 차단, 남의 데이터 안 보임, 저장소 출제·신고 동작 확인(시험 호출은 짧게). README·이 허브·루트 README 지도·소개 페이지 작동 방식 그림 갱신.

## 문제 저장소 (2026-11-20 추가)
현재 문제 1개당 제미나이 **2번**(문제 생성 + 채점·해설). 문제만 저장하면 1번만 줄어서 해설까지 저장한다.

- **객관식: 생성 때 해설까지 한 번에** — 정답·해설·**보기 A~D 각각 틀린 이유**를 함께 받아 저장. 채점·해설은 저장값으로 → AI 0번. 새 문제도 2번 → 1번.
- **주관식**: 문제·모범 답안·해설은 저장, 판정만 AI 1번 *(추천안 — 사용자 확인 전, 아래 미정 참고)*.
- **섞어 쓰기**: 묶음 = 범위(52) × 난이도(3) × 유형(2) = 312개.
  - 묶음에 10개 미만(처음엔 30, 2026-11-20에 10으로 낮춤) → 새로 만들어 저장
  - 10개 이상 → 약 90% 저장소, 약 10% 계속 새로 생성(다양성 유지)
  - **사용자가 이미 푼 문제는 제외**, 다 풀었으면 새로 생성
- **미리 채움 (2026-11-20)**: 객관식 52범위 × 3난이도 × 10문제 = 1,560문제를 Claude가 작성해 넣음(문제 파일·`import_bank.py`는 2026-11-22부터 비공개 저장소 Tracer-Route `bank/`로 옮김). 주관식은 미리 채우지 않음.
- **IP 연결 단원 보강 (2026-11-22)**: 단원 3이 시험 비중 25%인데 문제은행엔 10%(150문제)뿐 → 248문제 추가(3.1 +50, 3.2 +54, 3.3 +45, 3.4 OSPF +74, 3.5 +25) → 총 1,808문제, 단원 3 비중 22%.
  - 출력·설정 화면(`show ip route`, `show ip ospf neighbor` 등)을 보고 푸는 문제와 장애 해결 문제 위주. 객관식 단일 정답 형식은 그대로.
  - 검토 때 찾은 "정답 = 가장 긴 보기" 단서(기존 58%) → 새 문제는 오답 길이를 맞춰 25%(무작위 수준). 기존 1,560문제의 편향은 아직 그대로.
  - 형식 검사 통과, 2026-11-22 DB 입력(새로 248개, 기존 150개 중복 건너뜀). 공개 문구 1,808로 갱신.
- **보기 길이 편향 수정 (2026-11-22)**: 정답이 다른 보기보다 10자 이상 긴 572문제의 보기를 고침(오답을 그럴듯하게 늘리거나 정답 문장을 줄임, 오답이 정답이 되지 않게 확인). 정답이 가장 긴 보기인 비율 53% → 23%(무작위 25% 수준), 10자 이상 차이 0개. 문제 문장·정답·해설은 그대로. DB는 내용이 원래 파일과 같은 행만 고침(관리자 수정본 보호).
- **전체 내용 검수 (2026-11-22)**: 자동 검사(정답·보기 설명 일치, 빈·중복 보기, 해설의 보기 글자 언급, 중복 문제) 오류 0. 이어서 Sonnet 도우미 6개가 단원별로 1,808문제 전부 검수 → 의심 7건, 직접 확인해 6건 수정(정답 키가 틀린 문제는 0, 문제 문장이 애매하거나 해설이 어긋난 것). 보기 길이 수정 때 생긴 보기별 설명 어긋남 9건도 고침. 파일·DB 14개 행 갱신(문장이 바뀐 3개는 norm_hash도 갱신, 중복 없음 확인).
  - 남은 것: 팁 빈 칸 805개, 'Which two' 단일 정답 형식 24개.
- **세트 풀기·마이페이지 (2026-11-22, 사용자 요청)**: 문제를 한 세트(5·10·20, 기본 5)로 이어서 풀고 결과를 보여 줌. 마이페이지 탭에 단원별·난이도별 정답률과 풀이 기록(틀린 문제만 거르기). 헤더 탭이 3개가 돼 960px 이하에선 탭을 둘째 줄로. 다음: 틀린 문제 다시 풀기.
- **틀린 문제 다시 풀기·주관식 멈춤 (2026-11-22)**: 마이페이지에서 틀린 문제로 세트, 맞히면 빠짐(진도 통계 제외). 주관식은 사용자 결정으로 잠시 멈춤(`TRACER_SHORT=1`로 다시 켬). 출시 체크리스트는 비공개 저장소 Tracer-Route `docs/`.
- **비공개 전환 (2026-11-22, 사용자 결정)**: 웹 TRACER(공개 저장소·Vercel)는 그대로. 안드로이드 앱 코드·문제은행 원본(1,808문제)·출시 문서는 비공개 저장소 `DODO-YONG/Tracer-Route`(로컬 `~/Tracer-Route`)에만 둔다. 공개 저장소에서는 지웠지만 예전 커밋 기록에는 남아 있음. 웹은 Supabase DB에서 문제를 읽어 영향 없음.
- **앱 이름 (2026-11-22, 사용자 결정)**: Cisco Packet Tracer와 겹치지 않게 출시 이름은 **Tracer Route**(같은 날 traceroute → Tracer Route로 확정). 광고 넣은 안드로이드 앱 + 문제를 앱 안에 저장하는 방향 검토 중.
- **객관식은 문제은행 전용 (2026-11-20, 사용자 결정)**: 객관식은 제미나이로 만들지 않고 문제은행에서만 냄(안 받은 문제 우선, 다 받았으면 반복). 제미나이는 주관식 생성·판정과 "내 문제 해설"에만.
- **품질 관리** (틀린 정답 키가 여러 사람에게 반복되는 위험 대비)
  - 문제 신고 버튼, 신고 N건 이상이면 자동 출제 중지
  - 문제별 정답률 기록, 비정상적으로 낮으면 정답 키 오류 의심 표시
  - 관리자 문제은행에서 검토·수정·숨김
  - 생성 시 기존 문제와 거의 같으면 저장 안 함(중복 제거)
- **제외**: "내 문제 해설"(책·기출 붙여 넣기)은 저장소에 넣지 않음 — 저작권·개인 입력. 지금처럼 매번 AI.
- **용량**: 312묶음 × 30 ≈ 9,400문제 ≈ 20MB (Supabase 무료 500MB 안).
- **선택**: GitHub Actions로 밤에 제미나이 무료 한도 안에서 조금씩 미리 채우기.
- 정상 상태 객관식은 **문제당 AI 0번**(지금 2번).

## 소개와 이용 화면 분리 (2026-11-20)
- 사용자 요청: 소개(작동 방식 애니메이션 포함)와 실제 서비스가 한 페이지에 섞여 헷갈림 → 사용자가 골라서 보게. 소개는 복잡하지 않게 핵심만, 로그인·로그아웃은 분명하게.
- `/ccna/` 처음 화면(소개 보기 / 바로 이용하기 두 카드) → `about.html` 소개 · `app.html` 이용. 예전 `/ccna/#intro`·`#how`는 소개로 이동, github.io 주소는 새 주소의 같은 페이지로.
- 소개 구성: 한 줄 소개+예시 문제 → 쓰는 법 3단계 → 좋은 점 4개 → 작동 방식 그림 → 저장하는 것/안 하는 것 → FAQ 4개 → 시작 버튼.
- 작동 방식 그림(`docs/tracer-how.js`)을 새 구조로: 브라우저 · 구글 로그인 · TRACER 서버(Vercel) · 데이터베이스(문제은행) · 제미나이, 장면 4개(로그인 / 문제 받기 / 채점·해설 / 서브넷). Q-BRANCH 소개 페이지 `#how`도 같이 바뀜.
- 로그인 표시: 공용 부품 `tracer-auth.js` — 로그아웃 상태는 흰색 "Google로 로그인" 버튼, 로그인 상태는 "로그인됨 + 이름" + 별도 "로그아웃" 버튼(휴대폰은 이니셜 + 로그아웃). 관리자 페이지에도 로그아웃.
- 확인: 로컬 시험 서버(가짜 로그인)에서 세 페이지 로그인·로그아웃, 그림 재생, 375px 가로 넘침 없음, 콘솔 오류 없음.
