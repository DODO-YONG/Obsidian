# 💬 관리자 명령창 (웹 TRACER 관리자 페이지)

상위: [[ccna-coach]] · 관련: [[TRACER 고도화 계획]]

**웹 데모의 관리자 페이지 전용**(안드로이드 앱 Tracer Route와는 무관).

> **지금 상태(2026-11-23)**: 명령창·일괄 작업·삭제 예정 버튼은 **모의 관리자 화면에서만** 켜져 있다. 실제 관리자 화면에서는 화면에서 숨기고 서버도 거부(403). 켜려면 Vercel 환경변수 `TRACER_ADMIN_AI=1`(보기 필터는 실제 화면에도 있음). 관리자 페이지 맨 위 입력칸에 말로 명령하면, 그 명령을 **이미 화면에 있는 필터·버튼**으로 실행한다. AI가 DB를 직접 건드리지 않는다.

## 흐름
1. **규칙 먼저**(화면 `admin.html`의 `ruleCommand`): 기간(“1년”, “한 달”, “며칠”)·대상(신고·미접속·승인 대기…)·동사(보여줘/몇 명/지워줘)를 정해진 표현으로 알아듣는다. 제미나이를 부르지 않아 정확하고 무료 한도도 아낀다.
2. 규칙으로 안 되면 **제미나이**(`/api/admin/ask`): 정해진 명령 목록(enum)에서 하나만 고르게 하고, 예시를 주고, 온도 0.1. 서버가 값을 허용 목록 안으로 다시 맞춘다(`clean_command`). 명령 문장만 보낸다(이메일은 지워서 보냄, 사용자 데이터·DB 내용은 안 보냄). 명령 문장은 기록하지 않는다.
3. **확신 70% 미만**이면 바로 실행하지 않고 “이렇게 이해했어요: …. 맞나요?” → [맞아요, 실행]/[아니에요].
4. 실행 결과는 5종으로 구분해 최근 6개를 보여 준다.

| 표시 | 뜻 |
|---|---|
| 화면 바꿈 | 탭·필터를 바꿔 보여 줌 |
| 답변 | 숫자로만 답함, 화면은 그대로(“화면에서 보기” 버튼) |
| 실행함 | 확인창에서 ‘실행’을 눌러 데이터가 바뀜 |
| 취소 / 확인 필요 | 확인창에서 취소 / AI 확신이 낮아 대기 |
| 못 함 | 목록 밖 명령이거나 대상이 없음 |

## 할 수 있는 명령(= 화면 버튼 범위)
- 보기: 대시보드(7·14·30·90일), 사용자(상태·삭제 예정·N일 넘게 미접속), 활동 기록, 문제은행(출제 중지·정답률 낮음), 앱 신고(미처리/전체·기간).
- 숫자 답변: 전체·승인 대기·차단·삭제 예정·N일 미접속 사용자 수, 기간 접속자, 오늘 제미나이 호출, 미처리/기간 앱 신고, 출제 중지·출제 중 문제 수.
- 일괄 작업(대상 목록을 보여 주고 다시 물음): N일 넘게 미접속 사용자 **삭제 예정 표시**, 삭제 예정 모두 취소, 승인 대기 모두 승인, 미처리 앱 신고 처리 완료.
- 특정 사람 지정·문제 수정·설정 변경 등은 하지 않는다(못 함).

## 결정
- **‘지워줘’ = 삭제 예정 표시**(`profiles.delete_at`), 실제 삭제는 아직 없음. 그 사용자가 다시 접속하면 자동으로 풀린다. 실제로 지울지·유예 기간은 미정([[개발 보드]]).
- 일괄 작업은 사용자 탭·앱 신고 탭에 **버튼으로도** 있다(명령창은 그 버튼과 같은 함수를 부름). 사용자 행마다 ‘삭제 예정/예정 취소’ 버튼.
- 서버 `/api/admin/users-bulk`도 한 명씩 권한 검사(주인·자기 자신 제외, 다른 관리자는 주인만).
- 관리자(주인 외)의 명령 해석은 그 사람의 하루 AI 한도를 쓴다.

## 모의 관리자 화면 (시연·시험용)
- 주소 `/ccna/admin.html?demo=1` — 로그인 없이 열림. 머리말 [실제 관리자 | 모의 관리자] 전환 칸, 로고 옆 표시, 모의는 주황 테마.
- **새 관리 기능은 모의 화면에만 넣는다(2026-11-23 결정).** 실제 화면은 아직 데이터가 적어 필요 없음 → 지금 모습 그대로.
- 데이터: `docs/ccna/admin-demo.js`의 **브라우저 안 가짜 DB 생성기**. 실제 DB와 연결 없음, 새로고침하면 처음으로.
  - 기본 사용자 500명(100·300·500·1,000 선택, `&n=`), **활동 1년치**(약 13만 건), 앱 신고 250건, 문제 460개(범위 52 × 난이도 3, 지어낸 예시 문제).
  - 문제는 실제 문제은행(비공개 저장소)과 무관 → 고치거나 숨겨도 실제 서비스엔 영향 없음.
  - 씨앗 고정(`&seed=`)이라 같은 크기면 매번 같은 데이터. 이름은 지어낸 것, 이메일은 example.com.
- 명령 해석: 규칙 → 안 되면 `/api/demo/ask`(실제 제미나이, 로그인 없음, **하루 전체 30회 제한** `TRACER_DEMO_DAILY_AI`).

## 관리 화면 기능 (모의 전용)
**1단계 — 기본기**
- 정렬(사용자·문제은행·앱 신고), 페이지 나누기(사용자·활동 50개, 문제·신고 20개).
- 체크박스 선택 + 선택 줄(이 페이지 모두 / 필터 결과 모두 선택) → 일괄 작업: 사용자(승인·차단·차단 해제·삭제 예정·예정 취소), 문제(검토 완료·출제 중지·숨기기), 신고(처리 완료·다시 열기).
- 모든 일괄 작업은 확인창 → 실행 → **10초 동안 되돌리기**.
- 필터·정렬·페이지를 주소(`#users?idle=365&sort=last_asc&p=2`)에 저장 → 새로고침·뒤로 가기·링크 공유에도 유지.
- 대시보드·활동 기록 기간에 180일·1년 추가.

**2단계 — 자주 쓰는 화면**
- **오늘 할 일** 탭: 승인 대기·미처리 신고·같은 문제 중복 신고·출제 중지·정답률 30% 미만·1년 미접속·삭제 예정·새 가입(24시간)·오늘 제미나이 사용률. 카드를 누르면 필터 걸린 목록으로(카드 숫자 = 목록 숫자). 대시보드 타일도 클릭 이동.
- **사용자 상세 창**: 이름 클릭 → 1년 접속·채점·정답률·AI 호출, 약한 범위(정답률 낮은 순), 쓰는 기기, 관리자 메모(저장), 최근 활동 20건.
- 필터 보강: 사용자 가입 기간, 문제 글자 검색·난이도, 신고 이유·글자 검색.

**명령창 확장(새 기능과 연결)**: "오늘 할 일 보여줘", "AI 제일 많이 쓴 사람", "최근 7일 가입자", "어려운 OSPF 문제", "오타 신고", "같은 문제 신고 많은 순", "출제 중지 문제 모두 숨겨줘", "정답률 낮은 문제 출제 중지해줘", "차단된 사람 모두 해제해줘", "방금 거 되돌려줘". 서버 명령 목록에도 `show_todo`·`select_users`·`select_questions`·`undo_last`와 정렬·이유·난이도·주제어(30자, 글자만) 인자 추가.

**3단계 — 분석**
- 대시보드 **지난 기간 비교**(고유 접속자·채점·정답률·AI 호출·새 가입, ▲▼), 날짜별 줄에 **가입자 수**.
- **범위별 정답률**(낮은 순 10개 / 모두 보기) → 누르면 그 범위 문제은행을 정답률 낮은 순으로.
- **CSV 내보내기**: 사용자·활동·문제은행·앱 신고·명령 기록의 필터 결과 전체(엑셀 한글 깨짐 방지 BOM).
- 명령: "지난주랑 비교해줘", "약한 범위 보여줘", "사용자 목록 CSV로 받아줘".

**명령 기록(실행 추적)** — "명령 기록" 탭(모의 전용)
- 명령 하나마다: 입력 → 해석 경로(규칙 / AI·확신) → 해석된 명령 → 실행 종류(화면 바꿈·숫자 계산·버튼 실행) → 확인창·관리자 선택 → 결과·메시지 → 걸린 시간.
- 결과·경로로 거르기, 요약(AI 해석 비율·못 함 수), **못 알아들은 문장 복사**(규칙 보강용), CSV, 기록 지우기.
- **이 브라우저(localStorage)에만** 최근 300건 저장, 어디로도 보내지 않음. 실제 화면 서버 쪽은 활동 기록에 `명령창 → 명령 이름`만 남음(문장은 안 남김).
- **다시 실행**: 명령창에서 온 줄마다 "다시 실행" 버튼(같은 문장을 다시 실행, 위험한 작업은 확인창 다시), 명령 "3번 다시 실행해줘". 직접 클릭 줄은 제외.
- **기록에서 되돌리기**: 데이터를 바꾼 줄(명령이든 선택 줄 직접 클릭이든)마다 **번호(#)와 "되돌리기" 버튼**. 명령으로도 — "3번 되돌려줘"(번호), "승인한 거 되돌려줘"(그 종류의 최근 작업), "방금 거 되돌려줘"(가장 최근). 시간 제한 없음(10초 줄 버튼과 별개). 최신이 아닌 작업을 되돌리면 "뒤에 한 작업이 덮어써질 수 있어요" 확인. 되돌린 줄은 "되돌림", 되돌리기 자체도 기록. 새로고침 전 작업만(모의 데이터가 처음 상태로 돌아가므로 이전 줄은 "새로고침되어 불가").
- LangGraph 같은 라이브러리는 쓰지 않음. 단계(규칙 → AI → 사람 확인 → 실행)는 직접 짠 흐름이고, 이 탭이 그 실행 추적 역할.

**모의 데이터 도구**: 안내 줄 "승인 대기 10명 추가"·"처음 상태로"(확인 후 새로고침), 명령 "승인 대기 더미 10명 넣어줘"(차단·사용 중도, 최대 50명).
**탭 배치**: 모의 화면은 탭이 많아 머리말 아래 한 줄로 내려 가로 스크롤 없이 모두 보이게.

## AI 조회(SQL) + 제미나이 우선 (모의 전용, 2026-11-23)
- **해석 방식**: 명령창 옆 [제미나이 우선 | 규칙 우선] 전환(기본 제미나이 우선, 브라우저에 저장). 제미나이 우선은 모든 명령을 제미나이가 먼저 해석 → 실패·한도 초과·"해당 명령 없음"이면 규칙으로 대신. 확신이 낮아도 규칙과 같은 명령이면 진행. 실제 화면은 늘 규칙 우선(그리고 꺼져 있음).
- **기간은 아무 숫자**: 10일·45일·열흘·보름 등. 기간 칸에 "직접 입력…" 옵션, 명령이 준 값은 칸에 새 옵션으로 추가. 서버 명령 목록도 고정값 대신 범위(1~365, 미접속 ~3,650).
- **SQL 조회**: 찾기·목록·몇 명 같은 질문은 제미나이가 **읽기 전용 SQLite SELECT**를 만든다(`sql_query`). 제미나이에는 **표 구조와 명령 문장만** 보냄(데이터 안 보냄, 한 번 약 2,500토큰).
  - 실행은 **브라우저 안 SQLite(sql.js 1.10.3, 처음 조회 때만 약 700KB 받음)**에 모의 데이터를 올려서. 실제 DB와 무관.
  - 표: users · questions(correct_rate) · app_reports · activity(sub·verdict·source 펼침). 시각은 UTC 'YYYY-MM-DD HH:MM:SS'.
  - 읽기 전용 검사를 서버(`sql_problem`)·화면 양쪽에서: SELECT/WITH 한 문장만, INSERT·UPDATE·DELETE·DDL·PRAGMA 등 막음, 최대 1,000행.
  - "조회 결과" 탭: 제목·SQL(복사)·행 수·표·CSV. 결과가 사용자·문제·신고이고 `id`가 있으면 **행을 골라 기존 일괄 작업**(확인창·되돌리기 기록 그대로). 데이터 변경은 SQL이 아니라 늘 기존 버튼 경로로.
  - `SELECT`로 시작하는 문장은 제미나이 없이 바로 실행(기록에 "SQL 직접").
  - 실제 관리자 화면은 SQL 조회 안 함(서버가 `sql_query`를 none으로). 나중에 붙인다면 읽기 전용 DB 계정 + 시간·행 제한.
- 모의 화면 제미나이 한도: 사이트 전체 하루 **100회**(`TRACER_DEMO_DAILY_AI`).

**체험 입구**(누구나, 로그인 없이): 이용 화면 **머리말 "관리자 체험" 칸**(휴대폰에선 "체험") + 마이페이지 맨 위 "관리자 화면 체험해 보기" 카드 → `admin.html?demo=1`.
