# 💞 소개팅 앱 기획 (v0.1)

상위: [[dating]]

> ChatGPT 초안(Next.js + Expo + Vercel + Supabase, 웹·아이폰·안드로이드 동시)을 검토한 뒤 **Claude Code와 이 볼트에서 이미 쓰는 방식**에 맞춰 다시 짠 기획. 원칙: **추가 요금 0원**, 혼자 만들 수 있는 크기, 내가 직접 만들고 시험할 수 있는 구조.

## 1. 목표를 두 단계로 나눈다

| 단계 | 대상 | 비용 | 성공 기준 |
|---|---|---|---|
| **1단계 — 초대제 시험판** | 초대 코드를 받은 지인 ~20명 | 0원 | 가입 → 사진 인증 → 스와이프 → 매칭 → 채팅 → 신고·차단·탈퇴가 끝까지 동작 |
| **2단계 — 공개 출시** | 누구나 (한국) | **성인 인증 비용 발생** | 1단계 결과를 보고 따로 결정 |

이유: 모르는 사람끼리 만나고 채팅하는 서비스를 한국에 공개하면 **휴대폰 본인확인(PASS 등)으로 만 19세 이상 확인**이 필요할 가능성이 크다. 이 인증은 유료라 0원으로는 공개 출시가 안 된다. 1단계는 아는 사람만 초대해서 이 문제를 피한다.

## 2. 기술 구성 — 이미 쓰는 것 재사용

| 영역 | 선택 | ChatGPT 초안과 다른 점 · 이유 |
|---|---|---|
| 화면 | **HTML/JS 정적 페이지**(빌드 없음, 모바일 우선 PWA) | Next.js 대신. [[ccna-coach\|TRACER]]·[[heartline]]과 같은 방식이라 바로 만들고 고치기 쉬움 |
| 안드로이드 | **Capacitor**로 같은 화면을 앱으로 감쌈(2단계) | Expo로 따로 만들지 않음. Tracer Route와 같은 방식 → 코드 하나로 웹·앱 |
| 아이폰 | **안 함** | Apple 등록비 연 $99 → 0원 원칙과 충돌 |
| 백엔드 | **Supabase 무료**: Auth · Postgres(RLS + RPC 함수) · Storage(비공개) · Realtime | 같음. 서버 코드 없이 DB 함수로 처리 |
| 로그인 | **구글 로그인**(TRACER에서 이미 설정해 봄) | 이메일 가입 대신. Supabase 기본 메일은 일반 사용자에게 못 보내서 SMTP가 따로 필요함. 구글 로그인은 메일 발송이 필요 없고 이메일도 이미 확인된 상태 |
| 호스팅 | 1단계: GitHub Pages 또는 Vercel 무료 / 2단계: Cloudflare Pages 무료 | Vercel 무료는 비상업 전용 → 광고·결제를 붙이면 상업적 이용 허용되는 곳으로 |
| 코드 위치 | **비공개 저장소**(Tracer-Route처럼) | 개인정보를 다루는 앱이라 정책·관리자 코드를 공개 볼트에 두지 않음. 기획 메모만 이 위키에 |
| AI | **안 씀** | 사용자 프로필·대화를 외부 AI(제미나이 등)로 보내지 않는다. 추천은 조건 기반 |

> 확인 필요: Supabase 무료는 **프로젝트 2개까지**. TRACER가 하나를 쓰고 있으니 이 앱이 두 번째(마지막 자리)가 된다. 또 무료 프로젝트는 7일 동안 안 쓰면 멈춤 → 시험 기간엔 자주 접속.

## 3. 인증 — 무엇을 "인증 회원"이라고 부를지

| 배지 | 확인 방법 | 1단계 |
|---|---|---|
| 초대 회원 | 운영자가 발급한 초대 코드로 가입 | ✅ |
| 성인 | 생년월일 입력(만 19세 이상) + 초대한 사람이 아는 사람 | ✅ (자기 신고 수준) |
| **사진 인증** | 지정한 손동작 셀카를 찍어 내면 운영자가 프로필 사진과 같은 사람인지 눈으로 확인 | ✅ — 0원으로 가능한 핵심 차별점 |
| 신원 인증 | 휴대폰 본인확인(유료) | ❌ 2단계 결정 |

- 신분증·주민번호는 **받지도 저장하지도 않는다.** 인증 셀카는 심사 후 **지우고** 결과(승인·날짜·심사자)만 남긴다.
- "신원 인증"이라는 말은 1단계에서 쓰지 않는다(실제와 다른 신뢰를 주지 않도록).

## 4. 데이터 구조 (ChatGPT 초안의 구멍을 고친 버전)

**원칙: 사용자가 직접 바꿀 수 있는 칸과 운영자만 바꾸는 칸을 다른 테이블에 둔다.**

| 테이블 | 내용 | 누가 쓰나 |
|---|---|---|
| `profiles` | 닉네임·성별·지역(시/도 단위)·자기소개·관심사 | 본인만 수정. 남에게는 추천 함수로만 보임 |
| `member_status` | 상태(draft·active·suspended)·사진 인증 여부·노출 여부 | **운영자만**(초안은 이게 profiles 안에 있어서 사용자가 스스로 정지를 풀 수 있었음) |
| `private.user_private` | 생년월일 | 저장 함수(`set_birth_date`)로만 넣음. 앱에서 직접 읽기 불가 |
| `preferences` | 원하는 나이·성별·지역 | 본인만 |
| `invites` | 초대 코드·사용 여부 | 운영자 발급, 가입 함수가 사용 처리 |
| `photos` | 사진 경로·순서·심사 상태 | 본인 업로드. **상태는 항상 pending으로 시작**(트리거로 강제) |
| `verifications` | 사진 인증 신청·결과 | 본인 신청, 운영자 심사 |
| `swipes` | like / pass | 함수로만 기록. **pass는 30일 뒤 다시 추천**(사용자가 적을 때 금방 바닥나지 않게) |
| `matches` | 두 사람(작은 ID가 a) | 당사자만 조회 |
| `messages` | 매칭 ID = 채팅방 | 매칭 당사자만 읽기·쓰기, 차단되면 막힘 |
| `blocks` · `reports` | 차단 · 신고(+신고 순간 대화 사본) | 본인 제출, 운영자 처리 |
| `consents` | 약관·개인정보 동의 이력 | 본인 |

고친 점:
- **모든 테이블에 RLS 켜기**를 마이그레이션에 실제로 넣는다(초안은 말로만).
- 회원이 지워지면 연결 데이터도 지워지게 `on delete cascade` 통일 → **탈퇴가 실제로 됨**(초안은 매칭·차단·신고 때문에 삭제 실패). 신고 기록은 대상이 탈퇴해도 남도록 `set null`.
- 나이 기준 **만 19세**(초안은 18).
- `updated_at` 자동 갱신 트리거.

### 핵심 DB 함수
`claim_invite` · `set_birth_date` · `get_candidates`(인증·활성·서로 조건·차단·이미 본 사람 제외, 20명씩) · `swipe`(기록 + 서로 like면 매칭, 한 트랜잭션) · `send_message` · `mark_read` · `block_user`(매칭 종료 포함) · `report_user` · `delete_my_account`

### 남용 막기
- 하루 like 수·분당 메시지 수 제한(함수 안에서 검사).
- 사진은 **브라우저에서 줄이고 WebP로 다시 저장** → 용량 절약 + **위치 정보(EXIF) 자동 제거**.
- 사진은 비공개 버킷, 보여줄 때만 짧은 서명 주소.

## 5. 화면

1. 초대 코드 → 구글 로그인 → 약관 동의
2. 프로필(닉네임·성별·생년월일·지역·소개·관심사) + 사진 1~4장
3. 사진 인증(손동작 셀카) → "심사 중" 화면
4. **탐색**: 카드 스와이프(좋아요 / 패스)
5. **매칭 목록** → **채팅**(읽음 표시, 메뉴에 차단·신고)
6. 내 정보: 프로필 수정·노출 끄기·**탈퇴(즉시 삭제)**
7. **관리자**(`/admin`): 인증·사진 심사, 신고 처리, 정지·복구, 초대 코드 발급 — TRACER 관리자 페이지 방식 재사용. 권한은 DB에서 확인

다른 회원에게는 닉네임·나이·시/도·소개·관심사·승인된 사진만 보인다.

## 6. 만드는 순서 (단계마다 시험 통과 후 다음)

| # | 할 일 | 끝났다는 기준 |
|---|---|---|
| 0 | 결정(아래 표) + 비공개 저장소·Supabase 프로젝트 | 결정 완료 |
| 1 | **DB + RLS + 함수** 먼저 | **권한 시험 통과**: 남의 비공개 정보·남의 채팅 못 봄, 스스로 인증·정지 해제 못 함, 매칭 안 된 사람과 채팅 불가, 차단하면 양쪽에서 사라짐 |
| 2 | 가입·프로필·사진 | 초대 코드 없으면 가입 불가, 사진 EXIF 없음 |
| 3 | 관리자 심사 | 승인 전엔 탐색 불가 |
| 4 | 탐색·스와이프·매칭 | 서로 좋아요 → 매칭 1개만 생성 |
| 5 | 채팅 | 실시간 도착·읽음 |
| 6 | 안전·탈퇴 | 신고·차단·탈퇴 후 데이터 삭제 확인 |
| 7 | **초대 시험판** | 지인 테스트, 화면 시험은 `e2e-test-writer`로 GitHub Actions에서 |
| 8 | (결정 후) Capacitor 안드로이드 · 공개 출시 준비 | Play 데이트 앱 정책·계정 삭제 웹 링크·12명 14일 비공개 테스트 |

권한 시험(1단계)이 가장 중요하다. 소개팅 앱은 화면보다 **"누가 무엇을 볼 수 있나"가 틀리면 사고**가 난다.
