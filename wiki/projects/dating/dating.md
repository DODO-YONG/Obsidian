# 💞 dating — 소개팅 앱 (개발중)

상위: [[00_홈]]

사진 인증 회원끼리 스와이프 → 매칭 → 채팅하는 소개팅 앱. **1단계(DB·RLS·함수) + 2단계(가입 화면) 보안 검토 반영·시험 104개 통과**, Supabase 적용 전. 코드명 미정.

- **코드**: 비공개 저장소 `DODO-YONG/dating`(로컬 `~/dating`) — 이 볼트엔 기획·결정만

- **기획서**: [[소개팅 앱 기획_261123]] — 단계·기술·데이터 구조·화면·순서·결정할 것
- **핵심 가설·차별점**: [[소개팅 앱 핵심 가설·차별점_261123]] — 여성이 통제하는 앱, 첫 시장 서울의 외국인 여성, 목적 표시, "No more Hongdae boys"
- **그룹 미팅(크루) 아이디어**: [[소개팅 앱 그룹 미팅 기능_261124]] — 친구 2~4명이 크루로 다른 크루와 매칭해 같이 만남, 파티 모드까지 (**결정 2026-11-24**: 솔로·크루 선택형, 오프라인 주선 없음·앱 기능은 미국 출시 뒤, 양쪽 전원 동의, 2~3명 같은 인원, 파티 모드 안 함)

## 설계 결정
- **ChatGPT 초안을 버리고 다시 짬**(2026-11-23): 초안(Next.js + Expo, 웹·아이폰·안드로이드 동시, 이메일 가입)은 0원 원칙·한국 기준(만 19세·성인 인증)·RLS 구멍(사용자가 스스로 정지 해제 가능, 탈퇴 실패)이 있어서 이 볼트의 방식(HTML/JS + Supabase + Capacitor)으로 재구성.
- **1단계는 초대제 시험판**: 공개 출시엔 유료 성인 인증이 필요할 가능성이 커서 따로 결정.
- **로그인 = 구글 로그인**(사용자 결정, 2026-11-23): 이메일 가입은 인증 메일용 SMTP가 따로 필요해서. TRACER에서 설정해 본 방식.
- **외부 AI 안 씀**: 프로필·대화는 개인정보라 제미나이 API 등으로 보내지 않는다(앱 기능 기준. 개발 중 agy에게 코드를 맡기는 건 별개).
- **결정 4개**(2026-11-23 사용자 "추천대로"): 새 비공개 저장소 · 성별 남·여 두 개 · 이름은 나중에 · Supabase 무료 두 번째 자리는 쓰되 권한 시험을 로컬(PGlite)에서 먼저 통과한 뒤 만든다.
- **1단계 출발점** = 코드 비교 실험의 Claude 판(`output/2026_11_23_코드비교실험/a_final`, 시험 37/37). 여기에 초대·동의·사진·사진 인증·읽음·신고·남용 제한·채팅 목록을 더함(저장소 `docs/SPEC-stage1.md`).
- **agy가 비공개 저장소에서 일함**: `scripts/gemini.sh -d ~/dating` — 그 폴더만, `.env`·푸시 금지(시험 통과). Claude가 SQL, agy가 시험을 동시에 씀.
- **정한 규칙**: 초대 코드 없으면 가입 불가(운영자 예외) · like 24시간 50번 · 메시지 1분 20개 · 정지 회원은 메시지 못 보냄 · 같은 상대 신고는 24시간에 한 번 · 신고 때 최근 메시지 50개 사본 · 사진 상태는 사용자가 뭘 넣든 pending · 남의 승인 사진은 둘 다 자격 있고 차단 없을 때만.

- **2단계 화면을 미리 만듦**(2026-11-23, 오래 걸리는 일 먼저): `web/`에 로그인 → 초대·동의 → 프로필 → 사진 → 사진 인증 → 심사 대기. Supabase가 아직 없어서 `config.js`가 비면 **데모 모드**(가짜 서버, 코드 `DEMO1234`)로 돈다. 사진은 브라우저에서 1280px WebP로 다시 그려 EXIF를 없애고 업로드 전에 검사. Storage는 비공개 버킷 2개(`photos`·`selfies`), 남의 사진 파일은 `get_photos()`와 같은 조건에서만 서명 주소 발급.
- **agy 보안 검토 반영**(2026-11-23, 21건 전부 고침, 저장소 `docs/review_stage1_*`): 주요 결정 —
  - 가입 = 초대 코드 + 약관·개인정보 동의 둘 다. 프로필·생년월일·선호는 `save_profile()` 한 번에, **생년월일은 처음 한 번만**.
  - like 한도는 지워지지 않는 기록으로 셈(like→pass 우회 막음), 한도 검사는 사용자 단위 잠금.
  - 남의 사진은 **서로 후보 조건(선호까지)·매칭 상대**일 때만 → Storage 목록으로 전체 회원을 훑지 못함. 남는 위험(서로 후보인 사람 폴더는 목록에 보임)은 초대제라 받아들이고 공개 출시 전 다시 판단.
  - 승인 사진 바꿔치기 방지: DB에 걸린 파일은 사용자가 지우거나 다시 못 올림.
  - Storage 파일은 DB가 직접 못 지움 → 지울 목록(`storage_trash`)에 쌓고 운영자 화면이 정리.
  - **아이폰은 캔버스 WebP 저장이 안 됨** → JPEG로 대체(EXIF는 똑같이 사라짐).
  - 초대 코드는 헷갈리는 글자 뺀 8자리(40비트) + 틀리면 1초 지연.

- **방향 결정**(2026-11-23 브레인스토밍): 실제 출시·해외까지, 첫 대상은 **서울의 외국인 여성**, 여성 우선 규칙은 강하게, 스와이프 유지, 초대 보증제는 제외, 목적 표시는 남성 필수·여성 선택. 자세히는 [[소개팅 앱 핵심 가설·차별점_261123]].

- **출시 순서·아이폰**(2026-11-24): 서울 초대제 시험판(웹앱) → 미국 도시 하나에서 정식 출시(안드로이드 + 아이폰, Apple 등록비는 0원 원칙 예외) → 필리핀 → 인도네시아. 한국 정식 출시는 본인인증·사업자 등록이 필요해 나중에. 자세히는 [[소개팅 앱 핵심 가설·차별점_261123]] 11·12절.

- **1b DB 완료**(2026-11-24): 기획 결정을 DB 규칙으로. 숫자(like 한도·기한 등)는 `private.settings` 한 행에서 바꿈. 목적·도시가 안 맞는 대상에겐 pass도 막음, 전화번호는 이어진 9자리 기준. 시험 전체 180개 통과. 명세는 저장소 `docs/SPEC-stage1b.md`.

- **UI/UX 시안**(2026-11-24): Claude 디자인 캔버스(비공개) https://claude.ai/artifact/AUohEYULzVGrM2JchpFpDd — 휴대폰 10장(환영·목적·대화 시작·탐색·남성 한마디 like·받은 like·매칭·채팅 목록·채팅·내 정보) + 디자인 시스템 + 노트북 웹 시험판. 화면 규칙 `docs/SPEC-web-1b.md`에 맞춤. **메인 컬러 = A Latte**(2026-11-24 사용자 결정, 베이지·브라운 후보 3개 중: 크림 `#F7F1E8`·샌드 `#E6D3BC`·카라멜 `#D9A46E`·시나몬 `#8C5A36`·에스프레소 `#1C1511`). 다크(기본) 바탕 에스프레소, 카라멜 = 할 일 하나(라이트에선 시나몬), 세이지 `#8FBF9A` = 앱이 지켜 주는 것, 러스트 `#E8806A` = 다시 보기. 탐색 카드는 사진이 꽉 차는 형태. **라이트 모드 시안**도 있음(크림 `#F7F1E8` 바탕·흰 카드·시나몬 `#8C5A36` 버튼, 세이지·러스트는 진하게). 사진 위 글자는 두 모드 모두 어두운 그늘 위 밝은 글자, **기기 기본 글꼴만**(외부 폰트 금지 규칙), 영어 먼저·한/영 전환, 19+, "그녀의 질문"은 늘 코랄 상자. 아직 사용자 검토 전.

- **좋아요 한마디 = 첫 메시지**(2026-11-24 사용자 결정): 남성이 좋아요 때 쓴 한마디(그녀 질문에 대한 답)를 매칭 뒤 대화의 첫 메시지로 인정한다. 매칭 뒤 다시 답하게 하지 않는다. 시안 반영, **DB도 반영(1c)**: 매칭될 때 두 like의 한마디를 첫 메시지로 넣고(메시지 시각 = 매칭 시각, 채팅 목록에서 새 매칭이 위로), 한마디에 연락처·링크가 있으면 like 때 막음. 설정 `note_as_first_message`로 끌 수 있음. 시험 200개 통과.

- **관리자 심사 화면(1d)**(2026-11-24): 운영자도 표를 직접 못 읽어서(RLS) 목록 함수 6개를 더함(모두 `require_admin`). 화면 `web/admin.html` = 심사(사진·셀카 나란히 → 활성화) · 신고(신고 순간 대화 사본) · 회원(정지·복구) · 초대 · 정리(Storage 지울 파일). **활성화는 사진 인증 + 승인 사진 1장이 있어야만**(`admin_activate`가 `not ready`로 막음, 실수로 심사 안 된 사람을 내보내지 않게). 운영자 등록은 SQL 편집기에서 `private.admins`에 직접. 명세 저장소 `docs/SPEC-stage1d.md`.

- **개인정보 처리방침·이용약관 초안**(2026-11-24): 저장소 `web/privacy.html`·`terms.html`(영어 먼저, 한국어판이 우선). 보유 기간 제안 = 계정은 탈퇴 즉시 삭제, 인증 셀카 파일은 심사 뒤 7일 안, 신고 기록·대화 사본은 처리 뒤 1년. agy 법 검토(`docs/review_legal_by_agy.md`) 반영: 상대 성별·만남 목적은 **민감정보 → 따로 동의**, 자동 검사(연락처·사기 낱말)·자동 노출 밀림 고지, 국외 이전 항목, jsDelivr. 가입 화면에 링크·고지 펼침, 첫 화면 아래 상시 링크. agy: 생년월일 자가입력만으론 청소년보호법상 성인인증 불충족 위험 → **결정(2026-11-24 사용자): 서울 시험판은 운영자가 나이를 직접 아는 사람에게만 초대 코드를 준다(폐쇄 시험)**. 초대받은 사람이 다른 사람을 초대하는 기능은 두지 않는다. 모르는 사람에게 열 땐(공개 출시) 휴대폰 본인인증을 먼저.
