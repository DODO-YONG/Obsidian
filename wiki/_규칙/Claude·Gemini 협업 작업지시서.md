# 🤝 Claude·Gemini 협업 작업지시서

상위: [[페이지 작성 규칙]]

> 같은 볼트에서 Claude와 제미나이가 같이 일하기 위한 **공통 규칙의 원본**입니다. 2026-11-23에 제미나이가 두 번 검토하고 모든 항목에 동의해 확정했습니다. 협의 기록은 git 커밋 `a8c0542`에 있습니다.
> 각자에게만 해당하는 규칙은 `CLAUDE.md`(Claude)와 `GEMINI.md`(제미나이)에 있습니다(11번).

## 1. 이 폴더는 어떤 곳인가

- **LLM이 관리하는 개인 위키 + 에이전트 코드 저장소**입니다. 사용자는 자료를 모으고 질문만 하고, 읽기·요약·링크·정리·기록은 AI가 합니다.
- 세 층으로 되어 있습니다.
  - `raw/`: 원본 자료. **읽기 전용**이라 누구도 고치거나 지우거나 옮기지 않습니다.
  - `wiki/`: markdown 페이지. 프로젝트별로 `wiki/projects/<이름>/{sources,entities,topics}/`에 둡니다.
  - 규칙: `CLAUDE.md`, `GEMINI.md`, `wiki/_규칙/`
- 코드는 `agents/`(에이전트), `docs/`(공개 사이트), `scripts/`·`.github/workflows/`(자동 장치)에 있습니다.
- 모든 글은 **한국어로, 간결하게, 쉬운 말로** 씁니다.

## 2. 꼭 알아야 할 위험 세 가지

### 2-1. 공개 저장소이고, 5분마다 자동으로 커밋·푸시됩니다
Obsidian Git 플러그인이 파일이 바뀌면 5분 안에 커밋하고 GitHub 공개 저장소로 푸시합니다. **볼트에 쓰는 모든 파일은 곧 공개된다고 생각해야 합니다.** 예외는 `.gitignore`에 있는 경로뿐이고, `wiki/_inbox/`도 그 예외에 들어갑니다(5번).

### 2-2. 비공개 정보가 같은 폴더에 섞여 있습니다
`private/`, `.env`·`.env.*`(API 키·토큰), `*.private.*`, `reports/`, 키·인증서 파일이 디스크에 있습니다. 사용자의 원칙은 "개인정보·비자·면접 경험·`private/` 내용·키와 토큰은 **외부 AI로 보내지 않는다**"입니다.
- 제미나이는 Google AI Pro(유료 구독)이지만 개인용 약관이 적용됩니다. 설정에 따라 대화가 저장·검토되거나 서비스 개선에 쓰일 수 있습니다.
- 그래서 비공개 정보는 Claude 한 곳에만 둡니다.

### 2-3. 둘이 같은 폴더를 씁니다
같은 파일을 동시에 고치면 한쪽 내용이 사라집니다. 그래서 **파일마다 쓰는 사람을 미리 정해 둡니다**(5번).

4. 충돌이 거의 없습니다.

## 4. 역할 분담

### 4-1. Gemini
- **자료 읽기(ingest 1단계)**: `raw/`의 공개 자료를 읽고 요약 초안을 씁니다. 자료 1개에 초안 1개입니다.
- **대량 정리·교차 검증**: 큰 PDF·이미지·공식 문서를 한 번에 읽고, 기존 위키와의 모순 후보를 `> ⚠️ 모순:`으로 뽑아 둡니다.
- **조사**: 최신 정보, 공식 문서, 버전·가격을 확인합니다. 출처 URL을 꼭 적습니다.
- **최신성 점검**: TRACER 등이 쓰는 외부 API의 지원 중단, 무료 한도, 스토어 정책 변경을 확인합니다. 스스로 주기적으로 실행할 수단이 없으니 **사용자나 Claude가 요청할 때** 하고, 결과는 `_인수인계.md`에 남깁니다.
- **CCNA 공부 내용 초안**, 영상·이미지·스캔 PDF 내용을 글로 옮기기
- **검토 의견(두 번째 눈)**: 위키 페이지와 코드를 읽고 의견을 남깁니다. 직접 고치지 않습니다.
- **패치 초안**: 코드 수정안을 초안으로 씁니다(7-4).

### 4-2. Claude
- 코드 전부(`agents/`, `docs/`, `scripts/`, `.github/`, `.githooks/`, `.claude/`)와 git
- 위키 최종 반영: 인박스 초안을 옮기고 frontmatter·`[[링크]]`·`index.md`·`log.md`를 갱신합니다.
- 개발 보드, 프로젝트 허브, 루트 `README.md`
- 비공개 작업 전부(개인 기록·면접·비자·일정·비공개 저장소)
- 위키 점검(lint), 규칙 문서 수정
- **제미나이 부르기**: `scripts/gemini.sh`로 일을 맡기고 결과를 정리합니다(6번).

### 4-3. 애매할 때
공용 파일을 꼭 고쳐야 하면 직접 고치지 말고 인수인계 메모에 "이렇게 바꿔 주세요"라고 남깁니다.

## 6. 제미나이 부르는 방법 (Antigravity CLI)

사용자는 **Claude에게만 말하면** 됩니다. 제미나이가 필요한 일은 Claude가 아래처럼 맡기고 결과를 정리합니다.

```
scripts/gemini.sh "raw/projects/ccna/ospf.pdf 를 읽고 요약 초안을 wiki/_inbox/ 에 써 줘"
scripts/gemini.sh -m gemini-3.8-flash-medium "OSPF hello 간격 기본값을 공식 문서로 확인해 줘"
```

- **도구**: Google Antigravity CLI(`agy`, `~/.local/bin/agy`). Gemini CLI는 2026-06-18부터 Pro 계정 요청을 처리하지 않습니다.
  - 설치: `curl -fsSL https://antigravity.google/cli/install.sh | bash`
  - 처음 한 번 `agy`를 실행해 **Google OAuth**로 로그인합니다. "Google Cloud 프로젝트"는 유료 청구 방식이라 고르지 않습니다.
- **계정**: 사용자 Google AI Pro 로그인으로만 실행합니다. 스크립트가 API 키 변수를 지우고 실행하고, API 키 방식(`modelProvider`)이 켜져 있으면 멈춥니다. `agy`는 `.env`를 읽지 않습니다.
- **모델**: 기본은 `gemini-4-neon-high`입니다. 가벼운 일(요약·번역·점검)은 `gemini-3.8-flash-medium`으로 한도를 아낍니다. 목록은 `agy models`로 봅니다. 목록에 Claude 모델도 있지만 쓰지 않습니다.
- **안전장치** (`scripts/agy-settings.json`, 2026-11-23 미끼 파일로 시험해 통과):
  - `private/`·`.env`·`reports/`·`.git` 읽기는 거부합니다. 직접 읽기, 셸 `cat`, 검색 도구 모두 막혔습니다.
  - 셸 명령은 전부 거부합니다.
  - 쓰기는 `wiki/_inbox/`에만 허용합니다. 그 밖에 쓰려 하면 자동으로 거부됩니다. 헤드리스라 허락을 물을 수 없어서입니다.
  - 작업 폴더는 `wiki/_inbox/`이고, `GEMINI.md`는 볼트 루트에서 자동으로 읽힙니다.
- **보내는 내용**: 공개해도 되는 자료만 보냅니다. 비공개 저장소(Tracer-Route) 코드는 사용자가 허락하기 전에는 보내지 않습니다.
- **Mac Gemini 앱**: 사용자가 제미나이와 직접 이야기할 때 그대로 씁니다. 이 앱은 `GEMINI.md`를 자동으로 읽지 않으니, 앱으로 볼트 작업을 시킬 때는 "`GEMINI.md` 먼저 읽어"라고 말합니다. `CLAUDE.md` 맨 위에도 제미나이용 핵심 3줄이 있습니다.
- **사용자가 할 일**: `agy`에서 `/config` → Enable Telemetry 끄기(계정에 저장되는 설정)

## 7. 작업 흐름

### 7-1. 한 번의 작업
```
사용자 → Claude: "이 자료 제미나이한테 요약시켜서 위키에 넣어줘"
  → Claude: scripts/gemini.sh 로 제미나이에게 맡김
  → 제미나이: wiki/_inbox/ 에 초안 (+ 필요하면 인수인계 메모)
  → Claude: 초안 검토 → 위키 폴더로 옮김 → 링크·index·log·보드 갱신 → 인박스에서 삭제 → 커밋
```
사용자가 Mac 앱으로 제미나이에게 직접 시킨 경우에도 결과는 인박스에 두고, Claude에게 "인박스 정리해줘"라고 하면 됩니다.

### 7-2. 초안 형식: `wiki/_inbox/<제목>_YYMMDD.md`
형식은 `GEMINI.md`에 있습니다. frontmatter에는 `작성: gemini`, `검토상태: 미확인`, `출처`, `제안_위치`를 넣습니다.

### 7-3. 인수인계 메모: `wiki/_inbox/_인수인계.md`
맨 아래에 **추가만** 합니다. `## [YYYY-MM-DD] gemini → claude` 또는 `claude → gemini` 아래에 "한 일 / 부탁 / 주의"를 적습니다.

### 7-4. 패치 초안과 코드 직접 수정
- 패치 초안은 `wiki/_inbox/패치_<제목>_YYMMDD.md`에 씁니다. 내용은 바꿀 파일 경로, 이유, diff(또는 바꿀 코드), 확인 방법입니다. 반영은 Claude가 합니다.
- 사용자가 Mac 앱으로 제미나이에게 코드 수정을 **직접** 지시했다면 아래 조건에서만 고칩니다. 이 저장소의 코드는 고친 뒤 해야 할 후속 작업이 있기 때문입니다.
  - 후속 작업 예: `docs/` HTML을 고치면 `scripts/bump-site-version.sh` 실행, TRACER 화면을 고치면 Playwright 시험 수정, 커밋 전 비밀 검사, README 지도·`docs/map.html` 갱신
  - 조건:
    1. Claude가 같은 파일을 작업 중이 아닐 때만 고칩니다. 확인이 안 되면 사용자에게 묻습니다.
    2. 고친 뒤 `_인수인계.md`에 고친 파일과 남은 후속 작업을 적습니다. 후속 작업과 커밋은 Claude가 합니다.
    3. `.env*`, `.githooks/`, `.github/workflows/`, `.claude/`는 지시를 받아도 고치지 않습니다.

## 8. 내용 기준 (공개 저장소라서)
- 실명·연락처·주소, 사용자 개인 사정(건강·비자·면접·일정·금전)은 쓰지 않습니다.
- 키·토큰·비밀번호는 쓰지 않습니다. 예시가 필요하면 `<YOUR_KEY>`처럼 씁니다.
- 저작권 자료는 요약하고, 인용은 짧게 출처와 함께 씁니다. TRACER 문제은행 원본 문제는 쓰지 않습니다.
- **새 유료 서비스는 제안하지 않습니다.** 지금 쓰는 구독(Claude, Google AI Pro) 말고는 비용을 쓰지 않습니다.
- 추측은 `(추정)`으로 표시하고, 모순은 `> ⚠️ 모순:`으로 적습니다. 검토상태는 `미확인`으로 둡니다.
- **Google Workspace**: Drive·Docs·Sheets는 공개해도 되는 자료만 가져옵니다. Gmail·Calendar 내용은 볼트에 가져오지 않습니다. 애매하면 사용자에게 먼저 묻습니다.

## 9. 개발 보드 담당 표시
`wiki/개발 보드.md`의 할 일 끝에 담당을 붙입니다. 붙이는 건 Claude가 합니다.
- `[G]`: 제미나이
- `[C]`: Claude
- `[G]→[C]`: 제미나이가 초안을 쓰고 Claude가 반영

"보드 맨 위 거 해줘"라고 하면 Claude가 맨 위 항목을 보고, `[G]` 몫은 제미나이에게 맡깁니다.

## 10. 다시 정할 때
- 불편하거나 비효율적인 점을 발견하면 인수인계 메모에 제안하고, 사용자가 정합니다.
- **넓히는 기준**: 인박스 초안이 10개 이상 거의 고칠 것 없이 위키에 들어가면, 간단한 위키 페이지(source·topic)는 제미나이가 바로 쓰는 쪽으로 넓히는 것을 검토합니다. 이때도 공용 파일(`index.md`·`log.md`·보드)은 Claude만 고칩니다.
- **새 저장소**(예: 새 앱)를 시작할 때는 그 저장소의 주 담당(코드·git을 누가 할지)을 따로 정합니다.

## 11. 규칙 파일 나눠 관리하기

| 파일 | 담는 내용 | 고치는 사람 |
|---|---|---|
| **이 작업지시서** | 공통 규칙의 원본 | Claude(사용자가 정했거나 둘이 합의한 내용) |
| **`CLAUDE.md`** | Claude 몫(코드·커밋·비공개 작업·인박스 정리). 맨 위에 제미나이용 핵심 3줄과 이 문서 링크 | Claude |
| **`GEMINI.md`** | 제미나이 몫(인박스·초안·패치 형식·Workspace 범위·읽지 않는 경로). 맨 위에 핵심 3줄 | Claude가 반영, **제미나이가 수정안을 냄** |

운영 방법은 네 가지입니다.
1. 공통 규칙은 이 문서에만 쓰고, 두 파일에는 링크만 둡니다. 예외는 핵심 금지 3줄입니다.
2. `GEMINI.md`는 제미나이의 설명서라 제미나이 의견을 우선합니다. 고칠 점은 인수인계 메모에 남기고, 공통 규칙과 부딪히면 사용자에게 묻습니다.
3. 새 규칙이 둘 다에게 해당하면 이 문서에, 한쪽에만 해당하면 그쪽 파일에 씁니다. 애매하면 이 문서에 씁니다.
4. 이 문서가 바뀌면 Claude가 인수인계 메모에 `claude → gemini: N번 바뀜(요약)`을 남깁니다.
