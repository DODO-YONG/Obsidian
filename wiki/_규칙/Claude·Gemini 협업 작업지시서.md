## 1. 이 폴더는 어떤 곳인가

- **LLM이 관리하는 개인 위키 + 에이전트 코드 저장소**입니다. 사용자는 자료를 모으고 질문만 하고, 읽기·요약·링크·정리·기록은 AI가 합니다.
- 세 층으로 되어 있습니다.
  - `raw/`: 원본 자료. **읽기 전용**이라 누구도 고치거나 지우거나 옮기지 않습니다.
  - `wiki/`: markdown 페이지. 프로젝트별로 `wiki/projects/<이름>/{sources,entities,topics}/`에 둡니다.
  - 규칙: `CLAUDE.md`, `GEMINI.md`, `wiki/_규칙/`
- 코드는 `agents/`(에이전트), `docs/`(공개 사이트), `scripts/`·`.github/workflows/`(자동 장치)에 있습니다.
- 모든 글은 **한국어로, 간결하게, 쉬운 말로** 씁니다.

## 2. 꼭 알아야 할 위험 세 가지

### 2-1. 공개 저장소이고, 5분마다 자동으로 커밋·푸시됩니다
Obsidian Git 플러그인이 파일이 바뀌면 5분 안에 커밋하고 GitHub 공개 저장소로 푸시합니다. **볼트에 쓰는 모든 파일은 곧 공개된다고 생각해야 합니다.** 예외는 `.gitignore`에 있는 경로(`private/`, `wiki/_inbox/` 등)뿐입니다.

### 2-2. 비공개 정보가 같은 폴더에 섞여 있습니다
`private/`, `.env`·`.env.*`(API 키·토큰), `*.private.*`, `reports/`, 키·인증서 파일이 디스크에 있습니다. 사용자의 원칙은 "개인정보·비자·면접 경험·`private/` 내용·키와 토큰은 **외부 AI로 보내지 않는다**"입니다.
- agy(사용자 Google AI Pro 로그인)는 **Telemetry를 꺼서** 개선용 공유가 꺼져 있습니다(꺼도 서비스 제공·안전 목적 처리는 계속). 사용자가 이 조건을 알고 Claude와 같은 등급으로 정했습니다.
- 둘 다 `private/`를 읽고 쓸 수 있습니다. 공개 파일에서 `private/`를 언급하지 않는 규칙은 둘 다 지킵니다.
- 제미나이 **API 무료 키**(TRACER·CUPID)는 다릅니다: 학습에 쓰이므로 개인정보를 보내지 않습니다.

### 2-3. 둘이 같은 폴더를 씁니다
같은 파일을 동시에 고치면 한쪽 내용이 사라집니다. 그래서 **파일마다 쓰는 사람을 미리 정해 둡니다**(5번).

## 4. 역할 분담

### 4-1. Gemini
- **자료 읽기(ingest)**: `raw/` 자료를 읽고 위키 페이지(source·topic)를 바로 씁니다.
- **대량 정리·교차 검증**: 큰 PDF·이미지·공식 문서를 한 번에 읽고, 기존 위키와의 모순 후보를 `> ⚠️ 모순:`으로 뽑아 둡니다.
- **조사**: 최신 정보, 공식 문서, 버전·가격을 확인합니다. 출처 URL을 꼭 적습니다.
- **최신성 점검**: TRACER 등이 쓰는 외부 API의 지원 중단, 무료 한도, 스토어 정책 변경을 확인합니다. 스스로 주기적으로 실행할 수단이 없으니 **사용자나 Claude가 요청할 때** 하고, 결과는 `_인수인계.md`에 남깁니다.
- **CCNA 공부 내용**, 영상·이미지·스캔 PDF 내용을 글로 옮기기
- **검토(두 번째 눈)**: 위키 페이지와 코드를 읽고 고칠 점이 있으면 직접 고칩니다.
- **위키 반영·코드 수정·커밋**: 맡은 일은 끝까지(index·log·보드 갱신, 후속 작업, 커밋) 합니다.

### 4-2. Claude
- 여러 파일에 걸친 핵심 코드 수정(조각을 잇는 서버·화면), 비공개 저장소(Tracer-Route, 볼트 밖). 화면 시험은 기본 agy(7-5)
- 규칙 문서 수정, 위키 점검(lint)
- 일을 나누고 제미나이 결과를 확인
- **제미나이 부르기**: `scripts/gemini.sh`로 일을 맡기고 결과를 정리합니다(6번).

### 4-3. 애매할 때
같은 파일을 둘이 동시에 고치지 않는 것만 지키면 누가 해도 됩니다. 넘길 일은 인수인계 메모에 남깁니다.

## 5. 파일 권한

| 경로 | Gemini | Claude |
|---|---|---|
| 볼트 전체(`wiki/`·`docs/`·`agents/`·`scripts/`·규칙·`index.md`·`log.md`·보드) | ✏️ | ✏️ |
| `private/` 등 개인정보 | ✏️ (2026-11-23 사용자 허락) | ✏️ |
| `raw/` | 👀 읽기(쓰기는 설정으로 차단) | 👀 읽기 |
| `.env`·`agents/heartline/server/.env`(키) | 🚫 읽기 도구·셸 모두 차단 | 필요할 때만 |
| 셸·git 커밋 | ✅ (OS 샌드박스 안, `--no-verify` 차단) | ✅ |
| git 푸시 | 안 함 → Obsidian 자동 백업이 5분 안에 푸시 | ✅ |
| 볼트 밖(`~/Tracer-Route` 등) | 🚫 아직 안 엶 | 필요할 때만 |

- **충돌 막기**: 커밋은 `git add <내가 바꾼 파일>`로 골라서 합니다(`-A` 금지). 같은 파일을 동시에 고치지 않습니다. Claude가 `scripts/gemini.sh`로 맡긴 일은 맡긴 범위만, 사용자가 직접 시킨 일은 시작 전에 `git status`를 봅니다.
- 커밋 훅(`.githooks/pre-commit`)은 둘 다 거칩니다.
- 키 차단은 두 겹입니다: 읽기 도구는 deny 규칙, 셸은 OS 샌드박스(`enableTerminalSandbox`)가 `.env`를 `Operation not permitted`로 막습니다. 샌드박스라 셸에서 네트워크가 없어 푸시는 하지 않습니다.

## 6. 제미나이 부르는 방법 (Antigravity CLI)

사용자는 **Claude에게만 말하면** 됩니다. 제미나이가 필요한 일은 Claude가 아래처럼 맡기고 결과를 정리합니다. **사용자가 "제미나이한테"라고 말하지 않아도** Claude가 작업 중에 필요하다고 판단하면 직접 부르고, 부를 때마다 한 줄로 알립니다. 언제 부르는지는 `CLAUDE.md` 협업 칸에 있습니다.

```
scripts/gemini.sh "raw/projects/ccna/ospf.pdf 를 ingest 해서 위키에 반영하고 커밋해 줘"
scripts/gemini.sh -m gemini-3.8-flash-medium "OSPF hello 간격 기본값을 공식 문서로 확인해 줘"
```

- **도구**: Google Antigravity CLI(`agy`, `~/.local/bin/agy`). Gemini CLI는 2026-06-18부터 Pro 계정 요청을 처리하지 않습니다.
  - 설치: `curl -fsSL https://antigravity.google/cli/install.sh | bash`
  - 처음 한 번 `agy`를 실행해 **Google OAuth**로 로그인합니다. "Google Cloud 프로젝트"는 유료 청구 방식이라 고르지 않습니다.
- **계정**: 사용자 Google AI Pro 로그인으로만 실행합니다. 스크립트가 API 키 변수를 지우고 실행하고, API 키 방식(`modelProvider`)이 켜져 있으면 멈춥니다. `agy`는 `.env`를 읽지 않습니다.
- **모델**: 기본은 `gemini-4-neon-high`입니다. 가벼운 일(요약·번역·점검)은 `gemini-3.8-flash-medium`으로 한도를 아낍니다. 목록은 `agy models`로 봅니다. 목록에 Claude 모델도 있지만 쓰지 않습니다.
- **권한 설정** (`scripts/agy-settings.json`, 2026-11-23 시험 통과): 볼트 전체 읽기·쓰기·셸·git 커밋 허용, 셸은 샌드박스. 막는 것은 키 파일 읽기(도구·셸 `cat` 모두 거부), `raw/` 쓰기, `--no-verify`뿐입니다(시험: `.env` 거부, `raw/` 쓰기 거부, `private/` 읽기·`git commit` 성공).
  - 작업 폴더는 볼트 루트이고, `GEMINI.md`를 자동으로 읽습니다.
- **보내는 내용**: `private/` 포함 볼트 안 내용은 맡겨도 됩니다. 비공개 저장소(Tracer-Route)는 볼트 밖이라 아직 열지 않았습니다.
- **Mac Gemini 앱**: 사용자가 제미나이와 직접 이야기할 때 그대로 씁니다. 이 앱은 `GEMINI.md`를 자동으로 읽지 않으니, 앱으로 볼트 작업을 시킬 때는 "`GEMINI.md` 먼저 읽어"라고 말합니다. `CLAUDE.md` 맨 위에도 제미나이용 핵심 3줄이 있습니다.
- **추가 요금 0원**: agy 한도(주간 리필)가 다 되면 **유료 AI 크레딧을 쓰지 않고 멈춘다**. `scripts/agy-settings.json`에 `useG1Credits: false`, `gemini.sh`는 계정 설정에서 크레딧이 켜져 있거나 제미나이가 아닌 모델(목록의 Claude 등)을 고르면 멈춘다. 돈이 드는 다른 길(API 키, Google Cloud 프로젝트 로그인 = 종량제)도 쓰지 않는다. 사용자는 `agy` `/config` → Use AI Credits가 꺼져 있는지만 확인.
- **Telemetry**: ✅ 꺼 둠(2026-11-23 사용자 확인, `agy` `/config` → Enable Telemetry, 계정에 저장). 꺼도 서비스 제공·안전 목적 처리는 계속된다고 약관에 적혀 있음.

## 7. 작업 흐름

### 7-1. 한 번의 작업
```
사용자 → Claude: "이 자료 제미나이한테 요약시켜서 위키에 넣어줘"
  → Claude: scripts/gemini.sh 로 제미나이에게 맡김
  → 제미나이: 위키에 바로 반영 → 링크·index·log·보드 갱신 → 자기 파일만 커밋 (푸시는 Obsidian 자동)
  → Claude: git log 로 결과 확인(필요하면 고침)
```
사용자가 agy로 제미나이에게 직접 시켜도 같습니다. 인박스(`wiki/_inbox/`)는 이제 인수인계 메모와 임시 메모용입니다.

### 7-2. 쓰는 형식
위키 페이지는 `CLAUDE.md`·[[페이지 작성 규칙]] 그대로 씁니다. 제미나이가 쓴 페이지는 frontmatter에 `작성: gemini`를 넣습니다. 검토상태는 사용자가 말한 값만(모르면 `미확인`).

### 7-3. 인수인계 메모: `wiki/_inbox/_인수인계.md`
맨 아래에 **추가만** 합니다. `## [YYYY-MM-DD] gemini → claude` 또는 `claude → gemini` 아래에 "한 일 / 부탁 / 주의"를 적습니다.

### 7-4. 코드 수정
**기본 순서: Claude가 짜고 agy가 검토**합니다. agy가 먼저 짜도 Claude 사용량이 줄지 않았고, agy 검토는 Claude 사용량 0으로 진짜 문제를 찾아 줬습니다([[Claude·agy 코드 작업 비교 실험_261123]]). 코드 검토는 기본 모델(`gemini-4-neon-high`)이면 충분합니다.

제미나이도 코드를 직접 고치고 후속 작업까지 합니다: `docs/` HTML → `scripts/bump-site-version.sh`, TRACER 화면 → Playwright 시험, README 지도·`docs/map.html` 갱신. 여러 파일이 얽힌 큰 코드 작업은 Claude가 맡는 게 효율적입니다.

### 7-5. 큰 작업은 병렬로 나누기 (2026-11-23 사용자 결정)
목적은 나누는 것 자체가 아니라 **효율과 정확성**입니다. 여러 단계 작업을 시작할 때 Claude가 이렇게 나눕니다.

| 맡는 쪽 | 일 |
|---|---|
| **agy (Claude 작업과 동시에, 백그라운드)** | 명세만 있으면 혼자 끝낼 수 있는 덩어리: DB SQL 파일, 서버 시험·가짜 DB, **화면 시험(Playwright, 기본)**, 문서 초안, 다 짠 코드의 검토 |
| **Claude** | 조각을 잇는 핵심 코드(서버 API·화면), agy에게 줄 **명세**(파일 이름·함수 이름·돌려줄 모양), agy 결과 검토·수정, 브라우저 작업(Supabase·Vercel), 사용자 결정 받기 |

- **파일 단위로 겹치지 않게** 나눕니다. agy에게 "이 파일만 고치고 커밋하지 말 것"을 적어 주고, 그 파일은 끝날 때까지 Claude가 손대지 않습니다. 커밋은 Claude가 결과를 확인한 뒤 함께 합니다.
- 명세는 Claude가 그 모양에 맞춰 바로 코드를 짤 수 있을 만큼 정확하게 씁니다(예: `admin_report(p_days) → {days, cur, prev, daily…}`).
- agy 결과는 그대로 믿지 않습니다. 실행해 보고(시험 통과), 연결부를 확인합니다. 예: SQL 표가 빈 값을 막는데 서버가 빈 문자열을 보내던 문제를 검토에서 찾음.
- 핵심 코드 초안은 계속 Claude가 씁니다(7-4, agy 초안은 Claude 사용량을 줄이지 못함).
- 실제 예: 실제 관리자 화면 옮기기 — agy가 DB SQL(236줄)·서버 시험 47개를 쓰는 동안 Claude는 서버 API·화면을 작성. 줄 수로 agy 약 48%.

## 8. 내용 기준 (공개 저장소라서)
- 실명·연락처·주소, 사용자 개인 사정(건강·비자·면접·일정·금전)은 **공개 폴더에** 쓰지 않습니다(`private/`에).
- 키·토큰·비밀번호는 쓰지 않습니다. 예시가 필요하면 `<YOUR_KEY>`처럼 씁니다.
- 저작권 자료는 요약하고, 인용은 짧게 출처와 함께 씁니다. TRACER 문제은행 원본 문제는 쓰지 않습니다.
- **새 유료 서비스는 제안하지 않습니다.** 지금 쓰는 구독(Claude, Google AI Pro) 말고는 비용을 쓰지 않습니다.
- 추측은 `(추정)`으로 표시하고, 모순은 `> ⚠️ 모순:`으로 적습니다. 검토상태는 `미확인`으로 둡니다.

## 9. 개발 보드 담당 표시
`wiki/개발 보드.md`의 할 일 끝에 담당을 붙입니다. 붙이는 건 Claude가 합니다.
- `[G]`: 제미나이
- `[C]`: Claude
- `[G]→[C]`: 제미나이가 초안을 쓰고 Claude가 반영

"보드 맨 위 거 해줘"라고 하면 Claude가 맨 위 항목을 보고, `[G]` 몫은 제미나이에게 맡깁니다.

## 11. 규칙 파일 나눠 관리하기

| 파일 | 담는 내용 | 고치는 사람 |
|---|---|---|
| **이 작업지시서** | 공통 규칙의 원본 | Claude(사용자가 정했거나 둘이 합의한 내용) |
| **`CLAUDE.md`** | 저장소 규칙의 원본(둘 다 따름). 맨 위에 제미나이 안내 한 줄 | Claude |
| **`GEMINI.md`** | 제미나이 몫(같은 권한, 커밋 방식, 충돌 막기, Workspace 범위). `CLAUDE.md`를 따른다고 명시 | Claude가 반영, **제미나이가 수정안을 냄** |

운영 방법은 네 가지입니다.
1. 공통 규칙은 이 문서에만 쓰고, 두 파일에는 링크만 둡니다.
2. `GEMINI.md`는 제미나이의 설명서라 제미나이 의견을 우선합니다. 고칠 점은 인수인계 메모에 남기고, 공통 규칙과 부딪히면 사용자에게 묻습니다.
3. 새 규칙이 둘 다에게 해당하면 이 문서에, 한쪽에만 해당하면 그쪽 파일에 씁니다. 애매하면 이 문서에 씁니다.
4. 이 문서가 바뀌면 Claude가 인수인계 메모에 `claude → gemini: N번 바뀜(요약)`을 남깁니다.
