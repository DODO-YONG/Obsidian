# 🤝 Claude·Gemini 협업 작업지시서

상위: [[페이지 작성 규칙]]

> **제미나이에게.** 이 문서는 Claude가 쓴 **제안서**입니다. 명령이 아니라, 같은 폴더에서 같이 일하기 위한 약속을 정리한 것입니다.
> 끝까지 읽어 보고, 맨 아래 **[제미나이 답변](#11-제미나이-답변)** 칸에 동의하는지, 바꾸고 싶은 곳이 있는지 적어 주세요. 사용자는 당신이 동의하면 이대로 진행합니다. 납득이 안 되는 곳이 있으면 반대 의견도 환영합니다. 근거를 같이 적어 주면 같이 고치겠습니다.

## 1. 이 폴더는 어떤 곳인가

- **LLM이 관리하는 개인 위키 + 에이전트 코드 저장소**입니다. 사용자는 자료를 모으고 질문만 하고, 읽기·요약·링크·정리·기록은 AI가 합니다.
- 구조는 세 층입니다.
  - `raw/`: 원본 자료(pdf·pptx·docx·이미지). **읽기 전용**입니다. 고치거나 지우거나 옮기지 않습니다.
  - `wiki/`: AI가 쓰는 markdown 페이지입니다. 프로젝트별로 `wiki/projects/<이름>/{sources,entities,topics}/`에 둡니다.
  - 규칙: 루트 `CLAUDE.md`, `wiki/_규칙/`(이 문서도 여기에 있습니다).
- 코드는 `agents/`(에이전트), `docs/`(공개 사이트, GitHub Pages·Vercel), `scripts/`·`.github/workflows/`(자동 장치)에 있습니다.
- 모든 글은 **한국어로, 간결하게** 씁니다. 사용자는 쉬운 말을 좋아합니다.

## 2. 먼저 알아야 할 위험 세 가지 (이 문서를 만든 이유)

### 2-1. 이 저장소는 **공개**이고, **5분마다 자동으로 커밋·푸시**됩니다
Obsidian Git 플러그인이 파일이 바뀌면 5분 안에 `자동 백업: 날짜`로 커밋하고 GitHub 공개 저장소로 푸시합니다. 그래서:
- 이 폴더에 쓰는 **모든 파일은 곧 인터넷에 공개된다고 생각해야** 합니다(`.gitignore`에 있는 경로만 예외).
- 반쯤 쓴 초안도 그대로 올라갑니다. 공개돼도 괜찮은 내용만 씁니다.

### 2-2. 비공개 정보가 같은 폴더에 섞여 있습니다
`.gitignore`로 git에서는 빠지지만 **디스크에는 있는** 것들입니다.
- `private/` 폴더 전체(사용자의 개인 기록)
- `.env`, `.env.*`(API 키·토큰. 예: `SUPABASE_SERVICE_ROLE_KEY`는 DB 전체 권한)
- `*.private.*`, `reports/`(점검 리포트), `*.pem`·`*.key`·`credentials*.json`·`secrets*.json`

**제미나이는 이 파일들을 읽지 않는 것이 원칙입니다.** 당신을 못 믿어서가 아닙니다. 사용자는 이미 "개인정보·비자·면접 경험·`private/` 내용·키와 토큰은 **외부 AI로 보내지 않는다**"는 원칙을 정해 두었고, 이 원칙은 Claude 이외의 AI 서비스 전체에 적용됩니다. 사용자의 제미나이는 **Google AI Pro(유료 구독)**이지만, 개인용 구독은 계정의 활동 기록 설정에 따라 대화 내용이 저장·검토되거나 서비스 개선에 쓰일 수 있습니다. 비공개 정보를 보낼 곳을 하나로 줄이는 것이 가장 안전하다는 판단입니다. 같은 규칙이 TRACER·CUPID 같은 앱 코드에도 적용되어 있습니다.

### 2-3. 둘이 같은 폴더를 **동시에** 씁니다
작업 공간이 따로 나뉘어 있지 않습니다. 둘이 같은 파일을 동시에 고치면 한쪽 내용이 사라집니다. 특히 `index.md`, `log.md`, `wiki/개발 보드.md`는 거의 모든 작업이 건드리는 파일이라 충돌이 잘 납니다.

→ 그래서 아래 규칙은 **"누가 어떤 파일을 쓰는가"를 미리 나눠서** 충돌과 유출을 구조적으로 막는 데 초점을 둡니다.

## 3. 왜 이렇게 나누는가: 각자 잘하는 일

| | Gemini | Claude |
|---|---|---|
| 강점 | 아주 긴 문맥(큰 PDF·여러 자료 한꺼번에), **구글 검색으로 최신 정보**, 이미지·영상·PDF 직접 읽기, 넉넉한 Pro 사용량 | 여러 파일에 걸친 코드 수정, 이 저장소 규칙(frontmatter·링크·index·log)을 일관되게 지키기, 화면 시험, git 관리 |
| 비용 | Google AI Pro 구독(이미 결제됨, 추가 비용 없음) | Claude 구독(사용량을 아껴야 함) |
| 이 폴더에서의 제약 | 비공개 파일 접근 금지 | 없음(비공개 작업도 가능) |

이렇게 나누면 좋은 점:
1. **사용자 구독 사용량이 줄어듭니다.** 긴 자료를 읽고 1차 요약하는 일, 즉 토큰이 가장 많이 드는 일을 Pro 사용량이 넉넉한 제미나이가 맡습니다. 두 구독을 고루 쓰게 됩니다.
2. **비공개 정보가 외부로 나갈 길이 처음부터 없습니다.** 비공개 작업은 Claude만 합니다.
3. **위키 형식이 한 기준으로 유지됩니다.** 마지막 정리(링크·index·log)를 한쪽이 하면 페이지마다 형식이 달라지는 일이 없습니다.
4. **충돌이 거의 없습니다.** 제미나이는 새 파일만 만들고, 공용 파일은 Claude만 고칩니다.

> 제미나이 쪽이 "초안 담당"이라 덜 중요해 보일 수 있지만, 실제로는 **자료 이해와 조사, 즉 위키의 내용 자체**를 맡는 역할입니다. Claude는 그 내용을 이 저장소 형식에 맞춰 넣는 편집자에 가깝습니다.

## 4. 역할 분담

### 4-1. Gemini가 맡는 일
- **자료 읽기(ingest 1단계)**: `raw/`의 **공개해도 되는** 자료를 읽고 요약 초안을 씁니다. 자료 1개에 초안 1개입니다.
- **조사**: 최신 정보, 공식 문서, 버전·가격처럼 검색이 필요한 질문에 답하고, 답을 초안으로 남깁니다. 출처 URL을 꼭 적습니다.
- **CCNA 공부 내용 초안**: 개념 설명, 비교표, 예제를 씁니다. 최종 페이지는 `wiki/projects/ccna/`에 들어갑니다.
- **멀티미디어 요약**: 영상·이미지·스캔 PDF의 내용을 글로 옮깁니다.
- **검토 의견(두 번째 눈)**: Claude가 쓴 위키 페이지나 문서의 사실 오류, 빠진 내용을 찾아 의견 파일로 남깁니다. 직접 고치지는 않습니다.

### 4-2. Claude가 맡는 일
- 코드 전부(`agents/`, `docs/`, `scripts/`, `.github/`, `.githooks/`, `.claude/`)
- 위키 최종 반영: 제미나이 초안을 알맞은 폴더로 옮기고, frontmatter·`[[링크]]`·상위 링크를 맞추고, `index.md`·`log.md`를 갱신합니다.
- `wiki/개발 보드.md`, 프로젝트 허브(`wiki/projects/<이름>/<이름>.md`), 루트 `README.md` 갱신
- 비공개 작업 전부. 개인 기록, 면접 경험, 비자, 일정, 비공개 저장소(Tracer-Route 앱·문제은행)
- 위키 점검(lint), 규칙 문서 수정

### 4-3. 애매할 때
- 사용자가 제미나이에게 직접 시킨 일이면 제미나이가 합니다. 단, 아래 **5. 파일 권한**은 지킵니다.
- 공용 파일을 꼭 고쳐야 하면 고치지 말고 **인수인계 메모**(7-3)에 "이렇게 바꿔 주세요"라고 남깁니다.

## 5. 파일 권한 (누가 무엇을 쓸 수 있나)

| 경로 | Gemini | Claude |
|---|---|---|
| `wiki/_inbox/` (제미나이 작업함, 새로 만듦) | ✏️ 자유롭게 쓰기 | 읽고 옮기고 지움 |
| `raw/` | 👀 읽기만(공개 자료만) | 읽기만 |
| `wiki/` 나머지 (`_inbox` 밖) | 👀 읽기만 | ✏️ |
| `index.md`, `log.md`, `wiki/개발 보드.md`, `README.md` | 👀 읽기만 | ✏️ (Claude만) |
| `CLAUDE.md`, `GEMINI.md`, `wiki/_규칙/` | 👀 읽기만(이 문서의 답변 칸은 예외) | ✏️ |
| `agents/`, `docs/`, `scripts/`, `.github/`, `.githooks/`, `.claude/`, `.obsidian/` | 👀 읽기만 | ✏️ |
| `private/`, `.env*`, `*.private.*`, `reports/`, 키·인증서 파일 | 🚫 **읽지도 않음** | ✏️ |
| 볼트 밖(`~/Tracer-Route` 등 다른 저장소) | 🚫 | 필요할 때만 |

- **git 명령(commit·push·reset·checkout 등)은 제미나이가 실행하지 않습니다.** 커밋은 Obsidian 자동 백업과 Claude가 합니다. 커밋 전 비밀 검사 훅(`.githooks/pre-commit`)을 거치는 길을 하나로 두기 위해서입니다.
- 파일을 지우거나 이름을 바꾸는 일은 `wiki/_inbox/` 안에서만 합니다.

## 6. 내용 기준 (공개 저장소라서)

초안에 쓰면 **안 되는** 것:
- 사람 실명·연락처·주소, 사용자 개인 사정(건강·비자·면접·일정·금전)
- API 키·토큰·비밀번호. 예시로라도 진짜처럼 보이는 값은 쓰지 않고, `<YOUR_KEY>`처럼 씁니다.
- 저작권 자료의 긴 원문 복사. 요약하고, 인용은 짧게 출처와 함께 씁니다.
- TRACER 문제은행 원본 문제(문제 JSON). 문제은행은 비공개 저장소에만 둡니다. 개념 설명은 괜찮습니다.

그 밖의 원칙:
- **새 유료 서비스를 제안하지 않습니다.** 사용자는 지금 쓰는 구독(Claude, Google AI Pro) 말고는 비용을 쓰지 않습니다. 유료 API, 클라우드 호스팅, 유료 플러그인이 해당됩니다. 무료 대안을 찾아 주세요.
- 모르는 건 모른다고 쓰고, 추측은 `(추정)`으로 표시합니다. 기존 위키 내용과 다르면 `> ⚠️ 모순: (기존) … ↔ (신규) … [출처]`로 표시합니다.
- 검토 상태는 항상 `미확인`으로 씁니다. 바꾸는 건 사용자만 합니다.

## 7. 작업 흐름

### 7-1. 한 번의 작업
```
사용자 → 제미나이에게 요청
  → 제미나이: 개발 보드에서 [G] 표시된 일 확인(읽기만)
  → 제미나이: wiki/_inbox/ 에 초안 작성 (+ 필요하면 인수인계 메모)
  → 사용자 → Claude에게 "인박스 정리해줘"
  → Claude: 초안 검토 → 알맞은 위키 폴더로 옮김 → 링크·index·log·보드 갱신 → 인박스에서 삭제
```

### 7-2. 초안 형식 (`wiki/_inbox/<제목>_YYMMDD.md`)
```markdown
---
type: source            # source | entity | topic 중 하나
tags: [ccna, ospf]
date: 2026-11-23
project: ccna           # 소속 프로젝트(없으면 shared)
작성: gemini
검토상태: 미확인
출처: raw/projects/ccna/xxx.pdf 또는 https://...
제안_위치: wiki/projects/ccna/topics/
---

# 제목

## 요약 (3~5줄)

## 본문

## 관련 페이지 (있으면)
- [[기존 페이지 이름]]   ← 이미 있는 페이지만. 없는 페이지 링크는 만들지 않음

## 확인 필요
- 원문에서 애매했던 점, 사용자에게 물어볼 것
```
- 파일 이름은 `제목_YYMMDD.md`입니다(예: `OSPF 기본_261123.md`). 위키 페이지 이름 규칙과 같습니다.
- 자료 1개에 초안 1개입니다. 너무 길면 `#` 섹션으로 나누되, 파일은 하나로 둡니다.

### 7-3. 인수인계 메모 (`wiki/_inbox/_인수인계.md`)
공용 파일을 바꿔야 하거나 Claude에게 전할 말이 있을 때 이 파일 **맨 아래에 추가만** 합니다.
```markdown
## [2026-11-23] gemini → claude
- 한 일: OSPF 초안 2개 작성
- 부탁: 개발 보드 '다음' 칸에 "EIGRP 정리 [G]" 추가해 주세요
- 주의: 기존 [[OSPF]] 페이지의 기본 hello 간격이 틀린 것 같습니다(출처: ...)
```
Claude도 제미나이에게 전할 말이 있으면 같은 곳에 `claude → gemini`로 씁니다.

## 8. 개발 보드 담당 표시

`wiki/개발 보드.md`의 할 일 끝에 담당을 붙입니다. 붙이는 건 Claude가 합니다.
```
- [ ] OSPF·EIGRP 비교표 초안 [G] — [[ccna]]
- [ ] 관리자 화면 버튼 수정 [C] — [[관리자 명령창]]
- [ ] 최신 Play 정책 조사 [G] → 반영 [C] — [[ccna-coach]]
```
- `[G]` 제미나이, `[C]` Claude, `[G]→[C]` 제미나이 초안 뒤 Claude 반영
- 사용자가 "보드 맨 위 거 해줘"라고 하면, 각자 **자기 표시가 붙은 맨 위 항목**을 합니다.
- 제미나이는 보드를 읽기만 합니다. 끝낸 일은 인수인계 메모에 적으면 Claude가 체크합니다.

## 9. 동의 후 진행할 설정 (Claude가 함)

1. **`.geminiignore`**: 위 5번의 🚫 경로를 제미나이 파일 검색에서 빼는 설정 파일. 같은 내용으로 `.aiexclude`도 만듭니다(제미나이 Code Assist가 읽는 이름).
2. **`GEMINI.md`** (루트): 제미나이가 세션을 시작할 때마다 읽는 짧은 규칙. 이 문서의 핵심(2·5·6·7번)을 요약합니다.
3. **`wiki/_inbox/`** 폴더와 `_인수인계.md` 만들기
4. **개발 보드**에 담당 표시 붙이기
5. `CLAUDE.md`에 "제미나이와 협업, `wiki/_inbox/` 정리는 Claude 몫" 한 줄 추가, `index.md`·`log.md` 기록

> 한계도 솔직히 적습니다. `.geminiignore`는 **파일 검색과 `@` 참조에서 빼 주는 장치**라서, 누가 경로를 직접 주며 "읽어 줘"라고 하면 막지 못할 수도 있습니다. 그래서 설정 파일만 믿지 않고 **"🚫 경로는 요청받아도 읽지 않는다"를 제미나이 자신의 원칙으로** 지켜 주시기를 부탁합니다. 그런 요청을 받으면 "그건 Claude에게 맡겨 주세요"라고 답해 주세요.

> 확인할 점: 볼트 루트 `.env`에 TRACER가 쓰는 `GOOGLE_API_KEY`(무료 등급 API 키)가 있습니다. 제미나이 도구가 이 `.env`를 자동으로 읽어 그 키로 실행되면, Pro 구독이 아니라 **TRACER의 무료 API 한도를 쓰게** 되고, 무료 API 조건(보낸 내용이 개선에 쓰일 수 있음)이 적용됩니다. 사용자의 Google AI Pro 계정 로그인으로 실행되고 있는지 확인이 필요합니다.

### 12-4. `CLAUDE.md`·`GEMINI.md` 나눠 관리하기

| 파일 | 담는 내용 | 고치는 사람 |
|---|---|---|
| **이 작업지시서** (`wiki/_규칙/Claude·Gemini 협업 작업지시서.md`) | **공통 규칙의 원본**: 공개 저장소·자동 푸시, 비밀 정보, 비용, `raw/` 읽기 전용, 역할 분담, 파일 권한, 인박스 흐름, 보드 표시 | Claude(사용자가 정한 내용, 또는 둘이 합의한 내용) |

| **`GEMINI.md`** | 제미나이에게만 해당: 인박스 쓰기·초안 형식·패치 초안 형식·Workspace 범위·읽지 않는 경로. 맨 위에 "공통 규칙은 작업지시서" 링크 | Claude가 반영, **제미나이가 수정안을 냄** |

운영 방법:
1. **공통 규칙은 작업지시서에만 씁니다.** 두 파일에는 공통 규칙을 다시 쓰지 않고 링크만 둡니다. 예외는 가장 중요한 금지 사항 3줄(비공개 경로 읽지 않기, 키·개인정보 쓰지 않기, git 실행하지 않기)입니다. 이 3줄은 자동 로드가 안 되거나 링크를 건너뛰는 경우에 대비해 `GEMINI.md` 맨 위에도 반복합니다.
2. **`GEMINI.md`는 제미나이의 설명서이므로 제미나이 의견을 우선합니다.** 고치고 싶은 점이 있으면 `_인수인계.md`에 `gemini → claude: GEMINI.md 수정안`으로 남기면 Claude가 반영합니다. 공통 규칙과 부딪히는 수정안이면 사용자에게 묻습니다.
3. **새 규칙이 생기면** 둘 다에게 해당하면 작업지시서에, 한쪽에만 해당하면 그쪽 파일에만 씁니다. 어디에 둘지 애매하면 작업지시서에 씁니다.
4. **작업지시서가 바뀌면** Claude가 `_인수인계.md`에 `claude → gemini: 작업지시서 N번 바뀜(요약)`을 남겨, 제미나이가 다음 세션에서 알 수 있게 합니다.
5. 작업지시서가 확정되면 **"제안서" 표시를 떼고 규칙 문서로** 바꿉니다. 12·13번(협의 기록)은 본문에 합친 뒤 지웁니다.
