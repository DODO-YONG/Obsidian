# 📏 위키 효과 측정 (A/B 테스트)

상위: [[00_홈]]

이 위키가 토큰·시간을 얼마나 줄이는지 **같은 질문을 두 번** 답하게 해서 잰다.
지난 사용분의 절약량은 "위키 없이 했다면"이 존재하지 않아 계산할 수 없다 → 앞으로 A/B로 잰다.

- **도구**: `tools/wiki_ab_test.py` · 질문 목록 `tools/wiki_ab_questions.txt` (자유롭게 수정)
- **A (위키)**: `CLAUDE.md` 바로가기 표·`wiki/`·`index.md`를 활용해 답함 (2026-11-18 첫 측정 땐 "index 먼저" 강제)
- **B (위키 없이)**: `wiki/`·`index.md`·`log.md` 읽기를 권한으로 막고, `agents/`·`docs/`·`scripts/`·`raw/` 원본만 읽어 답함
- **공통**: 읽기 도구(Read·Grep·Glob)만. 수정·명령 실행·웹 검색 금지, `private/`·`.env` 읽기 금지. 구독 로그인으로만 실행(`ANTHROPIC_API_KEY`가 있으면 거부)
- **순서**: 질문마다 A·B 순서를 번갈아 바꿔 캐시가 한쪽에만 유리하지 않게 함

## 실행
```bash
python3 tools/wiki_ab_test.py --dry-run   # 확인만, 사용량 0
python3 tools/wiki_ab_test.py -n 1        # 질문 1개 시험 (호출 2회)
python3 tools/wiki_ab_test.py             # 전체 (질문 5개 → 호출 10회)
```
구독 사용량이 든다. 모델을 고정해 비교하려면 `--model sonnet` 등.

## 지표 읽는 법
- **읽은토큰** = 새 입력 + 캐시 새로 저장 + 캐시 재사용. 캐시와 무관하게 "모델이 실제로 읽은 양" → 주 비교 지표.
- **시간_s**: 답이 나오기까지 걸린 시간. 대부분 답 생성 시간이라 토큰 절약보다 차이가 작게 나올 수 있음.
- **턴수**: 도구를 몇 번 썼는지(파일을 몇 번 열었는지).
- **API요금환산**: API 요금 기준 참고치. 구독이라 실제 청구 없음.
- ⚠️ **정확도 확인 필수**: CSV의 `답` 열을 A·B 나란히 본다. 토큰이 적어도 틀리면 의미 없다.
- 한계: `CLAUDE.md`는 두 방식 모두 자동으로 읽힌다(같은 고정 비용). 질문이 5개뿐이라 경향 확인용이다.

### 해석 (2026-11-18)
- **이번엔 위키가 오히려 더 씀.** 질문 2개 모두 A가 토큰이 많았다. 답 정확도는 둘 다 맞음. B가 코드 줄 번호·모델명까지 더 자세했고, A는 "정확한 모델명 없음"이라고 답했다.
- **이유 1: 한 단계를 더 거친다.** A는 `index.md` → 허브 페이지 순서로 읽느라 매번 4턴. 턴마다 전체 맥락(약 4만 토큰, 대부분 캐시)을 다시 읽으므로 턴 1개가 곧 토큰 수만 개다.
- **이유 2: 원본이 이미 요약돼 있다.** 지금 볼트의 "원본"은 에이전트 코드인데, 각 `agents/*/README.md`(4~8KB)가 위키 허브와 거의 같은 역할을 한다. B는 README로 바로 가서 3~5턴에 끝냈다. `raw/`에는 아직 문서가 없다.
- **결론**: 코드 프로젝트 질문에는 지금 위키가 토큰을 아끼지 않는다. 위키의 이득은 **원본이 크고 읽기 어려울 때**(긴 pptx·pdf·회의록 여러 개) 나와야 한다 → `raw/`에 문서를 ingest한 뒤 그 문서에 대한 질문으로 다시 잴 것.
- 한계: 질문 2개·1회 측정이라 우연 차이가 크다.

### 해석 (2026-11-18, 두 번째: CLAUDE.md 요약판 적용 후)
- **바꾼 것**: `CLAUDE.md` 16KB → 4.4KB(상세 규칙은 [[작업 규칙]]·[[페이지 작성 규칙]]으로 이동), "index 먼저" 강제 → 바로가기 표.
- **효과 (같은 질문 2개, 같은 모델)**: 위키 방식 324k → 138k 토큰(**−57%**), 위키 없이 208k → 140k(**−33%**). 매 호출 새 입력도 약 2.2~4.2만 → 1.5~1.7만으로 줄었다.
- **이제 A·B가 거의 같다**(138k vs 140k, 시간 13s vs 15s). 위키 쪽이 손해 보던 "한 단계 더"가 사라졌다. 답은 넷 다 정확.
- 결론: 토큰을 가장 많이 줄인 건 **위키를 쓰느냐가 아니라 매번 읽히는 규칙서를 짧게 한 것**. 위키 자체의 이득은 여전히 큰 원본 문서를 ingest했을 때 다시 잴 것.
