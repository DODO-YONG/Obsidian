DY-004 · scripts/gemini.py

TWIN

사용 중

터미널에서 제미나이와 대화합니다. 앞 대화를 기억하고, 모델이 바쁘면 다음 모델로 넘어갑니다.

# 대화 모드 (/new 새 대화, /exit 끝)
python3 scripts/gemini.py
# 한 번만 묻기 / 이어 묻기
python3 scripts/gemini.py "질문"
python3 scripts/gemini.py -c "이어서 질문"

대화 기록은 볼트 밖(~/.local/state)에 저장되어 GitHub에 올라가지 않습니다.

DY-005 · agents/beginner-faq

PRIMER

실행 전

정한 분야의 초보자 질문 15개와 두 줄 답을 받아 answer.md로 저장합니다. 요청은 한 번만 보내고, 저장된 답이 있으면 다시 묻지 않습니다.

# 처음 한 번
cd agents/beginner-faq
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
# 실행
python ask.py

실행 전에 ask.py의 [내 분야]를 바꾸고, .env에 GEMINI_MODEL을 넣어야 합니다.

04물어본 것

작업하면서 물어보고 알게 된 것

터미널 세션에서 나눈 질문과 답을 짧게 정리했습니다. 눌러서 펼쳐 보세요.

Q1Obsidian 볼트로 AI를 쓰는 이 방식은 뭐라고 불러?›

정해진 이름은 없지만 LLM 위키(LLM이 관리하는 지식베이스), AI 세컨드 브레인, 기술 쪽에선 컨텍스트 엔지니어링·에이전트 메모리라고 부릅니다.

핵심은 Obsidian이 아니라 파일을 직접 읽고 쓰는 코딩 에이전트입니다. 질문할 때마다 원본을 검색하는 방식과 달리, 미리 읽고 정리한 위키가 계속 쌓입니다.

Q2이 방식은 토큰이 많이 들어?›

자료를 넣을 때는 많이 들고, 물어볼 때는 적게 듭니다. 정리할 때 원본을 통째로 읽고 여러 페이지를 고치지만, 질문할 때는 정리된 짧은 페이지 몇 개만 읽습니다.

상황결과
같은 자료로 여러 날 여러 번 질문위키 방식이 유리
여러 자료를 엮어서 묻기크게 유리 (연결이 이미 정리됨)
한두 번 보고 끝원본을 바로 묻는 게 쌈

토큰보다 큰 이득은 세션이 바뀌어도 맥락이 남는다는 점입니다.

Q3개인 비서처럼 할 일·공부에 쓰기 좋은 방법이야?›

잘 맞는 일: 쌓아 둔 자료로 작업하기, 공부한 내용을 연결해 두고 나중에 묻기, 나에 대한 맥락을 매번 설명하지 않기.

약한 일: 먼저 말을 걸지 않아서 알림·일정 관리는 캘린더가 낫고, 매일 바뀌는 정보나 짧은 일회성 질문은 위키 없이 묻는 게 빠릅니다.

Q4앱에서 한 작업과 터미널 작업이 연동돼?›

대화는 연동되지 않고, 파일과 git으로만 이어집니다. 같은 폴더를 고치니 서로의 파일과 커밋은 볼 수 있습니다. 대화 기록은 이 맥에 남아 있어 필요하면 읽어 볼 수 있습니다.

Q5터미널에서 cd /가 왜 안 먹혀?›

Claude Code는 시작한 폴더 밖으로 나가면 다음 명령에서 원래 폴더로 되돌립니다. 안전장치입니다. 다른 폴더에서 일하려면 그 폴더를 작업 폴더로 추가하거나, 처음부터 그 폴더에서 실행하면 됩니다.

05정리

터미널 작업에서 남은 것

폴더가 기준이다

어디서 실행하느냐에 따라 Claude가 읽는 규칙과 기억이 달라집니다. 볼트에서 실행하면 같은 맥락을 씁니다.

키는 .env에만

코드에는 키를 넣지 않고 .env에서 읽습니다. 공개 저장소에 올라가도 안전합니다.

요청은 아껴서

지시문은 먼저 다듬고, 요청은 한 번만 보내고, 받은 답은 저장해 다시 묻지 않게 했습니다.
